## 0. О документе

### 0.1 Назначение

Rust-версия развивалась как порт Python-ветки, но к 3.1.3 разошлась с ней по
нескольким важным решениям: свой punycode вместо `idna`, свой детектор кодировок
вместо `chardetng`, свой слой буфера обмена на WinAPI, релизная схема из 6 сборок
и обязательные гейты качества в CI. Ни одно из этих решений не зафиксировано в
форме требований — они существуют как код и как объяснения в `CHANGELOG.md`.

Документ нужен, чтобы:

- **зафиксировать** требования 3.1.3 в проверяемой форме (критерий + ссылка на
  функцию или гейт), а не в форме пересказа кода;
- **сохранить основания** решений, которые иначе будут «оптимизированы» обратно:
  почему статический CRT, почему musl, почему свой детектор кодировок, почему
  текст релиза пишет `gh`, а не action;
- **дать основу приёмки** для следующей версии: что считается регрессом, какие
  проверки обязательны, какие расхождения уже известны и приняты.

- Полное наименование: «Site Restorer» — восстановление сайта из веб-архива.
- Обозначение: SR-RS. Версия: 3.1.3 (Rust, edition 2024).
- Пакет: `site-restorer`; бинарник `site-restorer` (+ `.exe` на Windows).

### 1.2 Заказчик, разработчик, пользователи

| Роль | Описание |
|---|---|

проверяемыми артефактами и постоянными ссылками `releases/latest/download/<имя>`.

## 2. Назначение и цели создания

### 2.1 Назначение

По адресу сайта построить локальную статическую копию, пригодную для просмотра
без исходного хостинга, и отчёт о полноте копии — одним файлом, без установки,
без прав администратора, на Windows и Linux.

### 2.2 Цели и проверяемые признаки

| ID | Цель | Проверяемый признак | Чем подтверждается |
|---|---|---|---|
| Ц-1 | Копия открывается локально и выглядит как оригинал | Страницы, стили, картинки отдаются из папки `site` при любом локальном сервере | `tests/live` кейс `start-happy`; нагрузочный прогон `anekdot.ru`: 1197 из 1200 файлов, 1193 страницы |
| Ц-2 | Работает на любом сайте, сохранившемся в архиве | Успешные прогоны на разных CMS без настройки под движок | `tests/live`: 5 адресов разных стеков; эвристики `Index::resolve` |
| Ц-3 | Пользователь видит, что происходит | Этап, процент, скорость, потоки, ETA, четыре полосы по типам, журнал | `app.rs` (плитки, степпер, журнал), `core.rs → Progress` |
| Ц-4 | Архив не блокирует за высокую нагрузку | Серия 429 → срез потоков, пауза, продолжение с того же места | `core.rs` AIMD-контроллер, `Shared::pause` |
| Ц-5 | Прерванный прогон продолжается | Повторный запуск не качает готовое | `download` (файл есть и непуст), кейс `load-kill-resume` |
| Ц-6 | Понятно, чего в копии нет | Отчёт: покрытие, объём, типы, битые ссылки, отказы 404, ошибки | `core.rs → report`, `REPORT_TMPL` |
| Ц-7 | Ноль зависимостей у пользователя и минимум у сборки | Один бинарник, 4 прямые зависимости, статический CRT и musl | `Cargo.toml`, гейты сборки, размеры в лимитах |
| Ц-8 | Релиз воспроизводим и проверяем | Тег = версия, `--version` у каждого ассета, лимиты размера, контрольные суммы, ссылки лендинга живые | `build.yml` (test → rust → release), `links.yml` |

### 2.3 Что не входит в цели

| Не делается | Причина |
|---|---|
| Обход капчи, подмена User-Agent под браузер, ротация IP | Провоцирует блокировку архива; сознательный отказ (БЗ-3) |
| Восстановление динамики: корзина, вход, поиск, AJAX | Серверной части в архиве нет |
| Встроенный локальный веб-сервер | Отдельная задача; копию открывают любым сервером (ОГ-5) |
| Докачка больших файлов по HTTP Range | Архив отдаёт целые ответы (Б-6) |
| Сборки под macOS и 32-битный Linux | Нет проверяемого стенда и/или TLS-тулчейна (СВ-7, Б-14) |
| Платные API, телеметрия, аккаунты | Продукт локальный и без серверной части (БЗ-1, БЗ-2) |
| Установщик Windows (MSI/Inno) | Отдельный релиз; сейчас портативный exe (ЭК-1) |

## 3. Характеристика объекта автоматизации

### 3.1 Источник данных: CDX API Internet Archive

Две точки взаимодействия: `http://web.archive.org/cdx/search/cdx` (индекс) и
`http://web.archive.org/web/<ts>id_/<url>` (байты снимка). Схема в коде — `http`,
TLS-цепочка для архива не настраивается.

| Параметр | Значение в реализации |
|---|---|
| Отбор записей | `matchType=domain`, `filter=statuscode:200`, `collapse=urlkey` |
| Поля ответа | `timestamp, original, mimetype, statuscode` |
| Оценка объёма | `showNumPages=true&output=json`; распознаются `"numpages"` и голое число |
| Быстрый запрос | выполняется **всегда**, `limit=50000`, 3 попытки |
| Постраничный обход | только как резерв: `limit=20000`, `page=i`, не более 200 страниц, 3 попытки на страницу |
| Признаки усечения | в журнал при `≥ 50 000` адресов и при отказе страницы |
| Отказ источника | 429/5xx → пауза `Retry-After` или `10 × попытка` с; сеть → 5 с; далее `inv_failed` |
| Разбор ответа | свой парсер `parse_rows`: внешний массив — контейнер, шапка `timestamp` отбрасывается |

Почему быстрый запрос всегда: постраничный режим (`page=N`) у archive.org
поддерживается не для всех сайтов и у части доменов всегда пуст. Дефект «при
`numpages > 1` быстрый запрос не выполнялся вовсе, инвентарь получал 1 адрес
вместо тысяч» найден живым тестом и исправлен (`tests/live/README.md`, дефект №9).

### 3.2 Классы восстанавливаемых сайтов

| Класс | Что важно для алгоритма |
|---|---|
| Статические сайты | Ссылки в трёх формах кавычек, `srcset`, CSS `url()`, `<base>` |
| Bitrix (в т. ч. Aspro) | Кэш с хэшем в имени `bitrix/cache/(css\|js)/s1/...`, миниатюры `upload/resize_cache/iblock/...` |
| WordPress, MODX | Параметры версии в ссылках, минифицированные файлы |
| Крупные каталоги | Тысячи адресов, много типов файлов, обрывы на объёме |

Эвристики применяются только как разрешение «файла нет по точному пути» и не
меняют поведение для точных совпадений.

### 3.3 Пользователь и условия работы

Один пользователь, Windows 10/11 (x64/x86) или Linux x64, права обычного
пользователя, копия на локальном диске, доступ к `web.archive.org`. В ВМ и RDP
без аппаратного OpenGL окно не откроется — предусмотрены сообщение и CLI.

### 3.4 Сценарии использования

| ID | Сценарий |
|---|---|
| С-1 | Вставил адрес (или ссылку из архива/поиска) → «Начать» → получил `site` и `report.html` |
| С-2 | Прогон прерван (закрытие окна, обрыв, лимит архива) → повторный запуск продолжает |
| С-3 | Серия 429 → потоки срезаются, пауза, продолжение без вмешательства |
| С-4 | Автоматический прогон: `--cli` с параметрами, разбор вывода и кода возврата |
| С-5 | Работа в ВМ без OpenGL → окно сообщает причину и предлагает CLI-сборку |

## 4. Требования к системе

### 4.1 Требования к структуре системы

**Обязательно.** Один бинарник, 11 модулей, фича `gui` (по умолчанию включена).

| Модуль | Строк | Ответственность | Запрещено |
|---|---|---|---|
| `core.rs` | 1861 | конвейер, сеть, AIMD, сборка, проверка, отчёт | знать про egui и про ввод пользователя |
| `app.rs` | 1129 | окно, форма, прогресс, журнал, справка | делать сетевые операции в потоке интерфейса |
| `encoding.rs` | 673 | выбор кодировки, качество текста, нормализация UTF-8 | зависеть от сети и ФС |
| `sanitize.rs` | 541 | разбор адреса, чистка вставки | читать файлы и ходить в сеть |
| `main.rs` | 458 | точка входа, консоль, разбор флагов, CLI | содержать бизнес-логику |
| `paths.rs` | 280 | адрес → путь, нормализация, тип файла | обращаться к состоянию прогона |
| `puny.rs` | 268 | punycode RFC 3492 | зависеть от `idna`/ICU |
| `i18n.rs` | 207 | строки интерфейса RU/EN | форматировать числа по локали ОС |
| `clip.rs` | 134 | буфер обмена на WinAPI | работать вне Windows (стабы) |
| `pick.rs` | 75 | диалог выбора папки (shell32) | требовать COM-обвязку сверх `CoInitializeEx` |
| `tr.rs` | 28 | переводы сообщений ядра и CLI | хранить строки интерфейса |

**Стадии конвейера** (`core.rs → Engine::run`): инвентаризация → загрузка →
сборка → проверка → отчёт. Каждая стадия идемпотентна по своему результату:
`mirror/` переиспользуется, `site/` пересобирается с нуля.

**Схема выходного каталога** (обязательно, это контракт для пользователя):

```
<папка>\
  site\                 — готовая копия (её открывают локальным сервером)
  mirror\               — сырые файлы из архива
  data\inventory.jsonl  — по строке на адрес: {"url","path","type"}
  data\content-types.tsv — путь в копии и Content-Type ответа (для кодировок)
  report.html           — отчёт о покрытии
```

**Фичи и профиль сборки** (обязательно):

- фича `gui` включает `eframe` и всё оконное; `--no-default-features` даёт
  консольный бинарник без egui (в нём модули `app`, `clip`, `i18n`, `pick` не
  компилируются);
- профиль `release`: `opt-level = "z"`, `lto = true`, `codegen-units = 1`,
  `panic = "abort"`, `strip = "symbols"` — это источник размеров 1,3–7,5 МБ.

### 4.2 Требования к функциям

#### 4.2.1 Ввод адреса и вставка

| ID | Требование | Критерий приёмки | Реализация |
|---|---|---|---|
| ФТ-01 | Принимать адрес в любом виде: домен, URL со схемой в любом регистре, с путём, портом, якорем, завершающей точкой | Из каждой формы получается один и тот же домен | `sanitize.rs → sanitize_site`, `hostname_from_url`; тесты `common_forms`, `uppercase_scheme_and_host` |
| ФТ-02 | Чистить вставленное: BOM и невидимые символы, управляющие, переводы строк, markdown `[текст](ссылка)`, кавычки-ёлочки, `<...>`, повторные пробелы | Вставка из браузера, письма, документа даёт домен | `sanitize.rs → clean_payload`, `markdown_target`; тесты `paste_*` |
| ФТ-03 | Доставать настоящий адрес из ссылки-обёртки: `web.archive.org/web/<ts>/<url>` (с схемой и без), `google/yandex/bing/duckduckgo` (параметры `q`, `url`, `u`, `target`, `text`) | Возвращается исходный домен, а не домен поисковика | `sanitize.rs → from_redirect`; тест `paste_archive_and_search_links` |
| ФТ-04 | Различать две причины кириллицы: текст в русской раскладке (обратное отображение ЙЦУКЕН→QWERTY) и настоящий IDN-домен (punycode) | `зкщлгзщдюкг → prokupol.ru`; `прокупол.рф → xn--j1achbcce0a.xn--p1ai` | `sanitize.rs → finish`, `dekeyboard`; `puny.rs → domain_to_ascii`; тесты `paste_cyrillic_and_layout`, `idn_becomes_punycode`, `layout_is_detected` |

## Приложение Б. Пробелы и расхождения (не выданы за требования)

|---|---|---|---|

## Приложение В. Словарь терминов

| Термин | Значение |
|---|---|
| CDX | индексный API Internet Archive со списком снимков по адресам |
| Снимок | сохранённая копия страницы на дату, адресуется меткой времени |
| `id_` | режим отдачи снимка «как есть», без панели архива и переписывания ссылок |
| Инвентаризация | получение списка адресов и выбор самого свежего снимка для каждого |
| `mirror/` | сырые файлы из архива |
| `site/` | собранная копия с относительными ссылками и UTF-8 |
| Покрытие | доля скачанных файлов от числа адресов в инвентаре |
| AIMD | additive increase / multiplicative decrease — подбор конкурентности |
| `Gate` | ограничитель одновременных запросов с изменяемым лимитом (`Mutex` + `Condvar`) |
| Заглушка архива | ответ «этого снимка нет», который нельзя сохранять как контент |
| Мойибаке | «двойное кодирование»: UTF-8, прочитанный как однобайтовая кириллица |
| Ассет | файл релиза на GitHub (`SiteRestorer-…`) |

## Приложение Г. Отношение к Python-версии 2.4.2

| Тема | Python 2.4.2 | Rust 3.1.3 | Оценка |
|---|---|---|---|
| Носитель | PyInstaller, Python внутри, ~12 МБ | один бинарник, 1,3–7,5 МБ | улучшено |
| Зависимости | только stdlib | 4 прямые, 313 в дереве, свои punycode и детектор | компромисс: своя логика вместо крейтов |
| Инвентаризация | постранично при `pages > 1`, быстрый запрос — только если одна страница | быстрый запрос всегда, постранично — только как резерв | исправлен класс дефектов (Б-1 — остаток) |
| Разбор `pages` | три формата, включая `{"pages": N}` | два формата, объект не разбирается | регресс (Б-1) |
| Конкурентность | AIMD, минимум 2, максимум 24, потоки ≤ 24 | AIMD, лимит 1…24, потоки 1…64 | эквивалентно, границы шире |
| Кодировки | utf-8 → объявленная → cp1251; каскад по объявлению | BOM → utf-8 → объявление → статистика с оценкой качества, починка мойибаке | существенно лучше |
| Сборка ссылок | те же атрибуты и эвристики | то же + обратная эвристика «оригинал → миниатюра» | улучшено |
| Проверка ссылок | без фильтра JS-мусора | фильтр JS-мусора и внешних | улучшено |
| Интерфейс | tkinter/ttk, 880×740, 4 полосы, журнал | egui, 900×660, степпер, плитки KPI, сетка 2×2, пустое состояние | улучшено |
| Вставка адреса | системная вставка tkinter | свой слой WinAPI + разбор по паузе + средняя кнопка | улучшено |
| Настройки | `config.json` (язык, адрес, папка) | не сохраняются | регресс (Б-3) |
| Тесты | 17, в CI не запускались | 50, в CI обязательны + гейты (fmt, clippy, audit, deny, machete, typos) | существенно лучше |
| Живые тесты | не формализованы | 24 CLI-кейса и 7 GUI-кейсов на 3 стендах | добавлено |
| Поставка | один exe на архитектуру | 6 сборок + бандл + суммы, лимиты размера, гейт тега, проверка ссылок | добавлено |
| Совместимость с чужим `mirror/` | — | хеш запроса другой (Б-21) | несовместимо для адресов с `?query` |
