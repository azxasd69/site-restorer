Документ отвечает на один вопрос: **какой именно снимок каждого адреса попадает в копию и что
делается, когда он непригоден**. Требования формулируются здесь, а не в ТЗ, чтобы ТЗ оставалось
перечнем требований с критериями приёмки; ТЗ ссылается на этот документ.

---

## 1. Термины

| Термин | Значение |
|---|---|
| Адрес | Нормализованный адрес ресурса (`https://хост/путь[?запрос]`), одна запись инвентаря |
| Снимок | Один сохранённый архивом HTTP-ответ на адрес, с отпечатком времени (14 цифр) |
| Отпечаток | `timestamp` снимка из индекса |
| Целевая дата | Время, ближайший к которому снимок запрашивается у архива |
| Пригодный снимок | Снимок, содержимое которого можно положить в копию (правила — §5) |
| Свежесть файла | Дата фактически полученного снимка (`Memento-Datetime`), а не отпечаток из индекса |
| Добор | Получение более старого снимка того же адреса после непригодности свежего |
| Полнота копии | Отсутствие потерянных адресов и пустых файлов; каждая ссылка страницы имеет адресата в копии или в списке добора |
| Перезапись пути | Ситуация, когда два разных адреса дают один и тот же путь в копии |

---

## 2. Главное правило

1. **Свежесть первична.** Для каждого адреса в копию идёт **самый свежий пригодный** снимок
   из имеющихся в архиве.
2. **Старое не скачивается зря.** Если свежий снимок пригоден, более старые снимки того же
   адреса не запрашиваются — ни в индексе, ни как снимок.
3. **Полнота через добор.** Если свежий снимок непригоден (нет, пуст, служебная заглушка,
   не тот тип), берётся следующий по времени более старый — до первого пригодного.
   Исчерпание цепочки фиксируется как «нет пригодного снимка», а не как пустой файл.
4. **Набор адресов не сужается.** Список адресов строится по всей истории домена; ограничение
   по дате — явный параметр и не должно отрезать существующие файлы. Чего нет в списке, но на что
   ссылаются страницы, добирается отдельным проходом (§8).
5. **Один путь — одна версия.** Если несколько адресов дают один путь в копии, остаётся самый
   свежий; остальные не скачиваются вовсе, факт фиксируется счётчиком (§9).
6. **Свежесть видна.** Дата каждого снимка пишется в журнал и отражается в отчёте: копия не может
   быть свежее архива, и пользователь должен это видеть (§10).

---

## 3. Механика архива, на которой это держится

| Факт | Следствие для нас |
|---|---|
| Индекс отдаёт строки, отсортированные по `urlkey`, затем по времени | «Первая» запись = самый **старый** снимок; так работает `collapse=urlkey` |
| Воспроизведение `/web/<ts>id_/<адрес>` отдаёт снимок, **ближайший** к `<ts>` | Подставив целевую дату «сейчас», получаем самый свежий снимок без знания его отпечатка |
| Ответ содержит `Memento-Datetime` — фактическое время снимка | Свежесть файла известна бесплатно, без дополнительных запросов |
| Ответ содержит `X-Archive-Src` (файл WARC) | В журнал можно писать источник — полезно при разборе |
| Нет снимка — ответ 404 без `Memento-Datetime` | Отсутствие отличается от сбоя и от пустого файла |
| `limit=-N` возвращает последние N строк **всего результата** | Для точечного адреса это последние снимки; для домена — последние по алфавиту адреса, поэтому для домена не годится |
| `from=`/`to=` ограничивают выборку по времени | Окно — инструмент полноты набора, а не свежести отдельного файла |

Замеры, подтверждающие таблицу: [plans/2026-11-snapshot-freshness.md](../plans/2026-11-snapshot-freshness.md) §5.

## 4. Алгоритм

### 4.1 Инвентаризация

```
target = (режим newest → сегодня; as-of → заданная дата; oldest → отпечаток из индекса)
rows   = CDX(домен, filter=statuscode:200, collapse=urlkey, limit=50000[, from=--since])
items  = rows → нормализованный адрес → путь копии, вид файла, отпечаток
items  = дедупликация по пути копии (§9)
items  = сортировка по адресу; при --limit — обрезка хвоста
```

Инвентарь сохраняется на диск (`data/inventory.jsonl`) и используется повторно при повторном
прогоне: список адресов не запрашивается заново, если он есть и относится к тому же хосту и режиму.

### 4.2 Получение файла

```
первая попытка: /web/<target>id_/<адрес>
  пригоден → записать, зафиксировать дату снимка, готово        # старые не запрашиваются
  нет снимка (404) или пусто/заглушка → цепочка добора (§6)
  сбой архива (5xx, таймаут, 429) → повтор по ФТ-37/ФТ-38, НЕ добор
  ошибка после повторов → файл в ошибки (не «нет снимка»)
```

Цепочка добора: один запрос списка последних снимков адреса, затем перебор от свежего к старому,
не более `--fallback-depth` попыток (по умолчанию 5). Каждый шаг — тот же `/web/<ts>id_/`.

### 4.3 Что попадает в копию

Файл пишется только после успешной проверки пригодности и успешной записи (ФТ-35).
Дата снимка, отпечаток и признак добора сохраняются в журнале сборки и в инвентаре прогона.

## 5. Пригодность снимка

| Признак в ответе | Решение | Действие |
|---|---|---|
| 200, размер > 0, для страницы есть разметка (`<html`, `<!doctype` в первых 2 КБ) или файл не-HTML | пригоден | записать |
| 200, размер = 0 или только пробелы | непригоден | добор |
| 200, но нет `Memento-Datetime` и тело — страница-заглушка архива | непригоден | добор |
| 404 архива | снимка нет | добор |
| 3xx с `Location` на тот же хост | следуем (ФТ-44), оцениваем конечный ответ | по результату |
| 3xx без пригодного `Location` (внешний редирект) | непригоден как содержимое | добор |
| 5xx архива, 429, таймаут, обрыв | сбой, а не отсутствие | повтор по расписанию; добор не запускается |
| 200, страница обещана, а содержимое — двоичный файл | пригоден как файл (ПРМ-14) | записать, страницей не считать |
| Архив вернул чужой домен (после редиректа) | непригоден | добор, запись в журнал |

Порог «страница без разметки» — эвристика, поэтому он настраиваемый (`--stub-bytes`, по умолчанию
256 байт) и всегда попадает в журнал строкой `snapshot:stub:<адрес>`: ложное срабатывание не должно
быть незаметным.

**Различие «нет снимка» и «сбой» принципиально:** добор при сбое маскировал бы недоступность архива
старой копией и выдавал её за свежую.

---

## 6. Добор по времени

```
CDX(адрес, fl=timestamp, filter=statuscode:200, limit=-N)   # N = --fallback-depth, 5
для ts от свежего к старому:
    если ts уже пробовали — пропустить
    ответ = /web/<ts>id_/<адрес>
    пригоден → записать, маркер snapshot:fallback:<ts>
```

- Добор запускается **только** по признакам «нет снимка» и «непригоден» (§5).
- Стоимость: один запрос индекса и до N снимков на непригодный адрес; на живых сайтах доборов нет.
- Маркеры журнала: `snapshot:fresh`, `snapshot:fallback:<ts>`, `snapshot:none`.
- В отчёт: «доборов N», «без пригодного снимка M».

---

## 7. Окно по времени (`--since`)

Окно нужно, чтобы не тащить давно удалённые адреса, но оно же и режет полноту. Поэтому:

| Что | Как берётся |
|---|---|
| Страницы (HTML) | с окном: `from=<дата>` — адреса, живые в окне |
| Ресурсы (стили, скрипты, изображения, шрифты, прочее) | без окна: полная история, иначе современная страница останется без старых картинок |
| Совпадение адреса в обоих списках | остаётся запись из списка с окном (она свежее) |

По умолчанию окно **выключено** (полная история). При включении в отчёт идёт строка
«адреса ограничены окном с <дата>, файлов вне окна не будет» — это предупреждение о потере полноты.

---

## 8. Добор по ссылкам (полнота набора)

После первой сборки известны все цели ссылок. Если цель отсутствует в копии, адрес того же хоста
и не превышен предел `--rescue-limit` (по умолчанию 500 адресов, 0 — выключить):

1. адрес добавляется в список добора;
2. снимок запрашивается по правилам §4.2 (свежий, затем добор по времени);
3. полученное кладётся в зеркало, сборка повторяется инкрементально (только новые файлы).

Маркеры: `rescue:try:<n>`, `rescue:ok:<n>`, `rescue:fail:<n>`. В отчёт — строка «добрано по ссылкам».
Проход выполняется не более одного раза за прогон: добор не должен превращаться в рекурсивный обход
всего архива.

---

## 9. Один путь — одна версия

Путь в копии строится из пути адреса, поэтому разные адреса могут дать один файл:
`/` и `/index.html`, `/api/` и `/api/index.html`, страницы разных поддоменов.

| Правило | Действие |
|---|---|
| Группировка | адреса группируются по пути копии до загрузки |
| Выбор | остаётся адрес с самым свежим снимком (по отпечатку из индекса); при равенстве — адрес каталога (`…/`), затем более короткий |
| Остальные | не скачиваются вовсе; счётчик `path_collisions` |
| Поддомены | путь включает хост для всех хостов, кроме основного: `mail.example.com/index.html` |
| Совместимость | если в архиве один хост, дерево копии не меняется; журнал с меткой формата 2 |

Это одновременно и полнота (ничего не теряется молча), и экономия (лишние файлы не качаются).

## 10. Журнал, свежесть и повторный прогон

Запись журнала сборки на файл: путь, размер, время изменения, вид, цели ссылок, **отпечаток снимка,
дата снимка, признак добора**. Метка файла: `#journal 2 <версия> <хост> <режим> <окно>`.

| Ситуация | Поведение |
|---|---|
| Повторный прогон, снимок не старше `--refresh-days` (30) | файл не перекачивается |
| Повторный прогон, снимок старше TTL | файл перекачивается один раз, копия обновляется |
| `--refresh` | TTL = 0: каждый файл проверяется заново |
| Режим `oldest` | журнал работает как в 3.4.0 (сравнение размера и времени) |
| Смена режима или окна | журнал не применяется, копия собирается заново |

Правило «не качать старое» проверяется счётчиком: при живом сайте число снимков, запрошенных
по цепочке добора, равно нулю.

## 11. Отчёт

Добавляются плитки и строки:

| Показатель | Смысл |
|---|---|
| Самый новый / самый старый снимок | крайние даты `Memento-Datetime` в копии |
| Распределение по годам | сколько файлов какого года |
| Старше 1 / 3 / 5 лет | предупреждение: «копия не свежее архива» |
| Доборов / без пригодного снимка | работа цепочки §6 |
| Перезаписей путей | работа §9 |
| Добрано по ссылкам | работа §8 |
| Список обрезан / окно включено | предупреждения о потере полноты |

Отчёт не должен выглядеть «свежим» по умолчанию: если 90 % файлов старше трёх лет, это видно
в первой строке сводки.

## 12. Параметры

| Параметр | Значение по умолчанию | Смысл |
|---|---|---|
| `--snapshot newest\|oldest` | `newest` | режим выбора снимка |
| `--as-of ГГГГ[-ММ[-ДД]]` | нет | целевая дата; включает режим «на дату» |
| `--fallback-depth N` | 5 | сколько более старых снимков пробовать; 0 — выключить добор |
| `--refresh-days N` | 30 | старше какого возраста снимок перекачивается |
| `--refresh` | нет | проверить свежесть всех файлов (TTL = 0) |
| `--since ГГГГ[-ММ[-ДД]]` | нет | окно для страниц |
| `--rescue-limit N` | 500 | предел добора по ссылкам; 0 — выключить |
| `--stub-bytes N` | 256 | порог «пустой страницы» |
| `--threads N` | по ядрам | как в 3.4.0 |

Совместимость: `--snapshot oldest` без новых параметров воспроизводит поведение 3.4.0.

## 13. Крайние случаи

| Случай | Решение |
|---|---|
| Адрес есть в индексе, но снимков с кодом 200 нет | «нет пригодного снимка», файла нет, строка в отчёте |
| Свежий снимок — страница-заглушка сайта («сайт закрыт») | считается пригодным: это подлинное содержимое сайта; год виден в отчёте |
| Страница 2026 ссылается на стиль 2019 | нормально: каждый файл берётся самым свежим из существующих |
| Изображение есть только за 2014 | берётся 2014: полнота важнее единой эпохи |
| Ответ пришёл сжатым | разжимается прозрачно (ФТ-44) |
| Снимок отдаёт другой домен после редиректа | не принимается (§5), фиксируется |
| Прогон прерван | неполный файл не остаётся под итоговым именем (ФТ-34); при повторе журнал учитывает уже полученное |
| Длинный путь Windows | обработка по ОШ-7 (ФТ-45) |
| Одновременно идут два прогона в одну папку | вне области (Д-14) |

## 15. Риски и ограничения

| Риск | Проявление | Мера |
|---|---|---|
| Архив нестабилен (429/503/504) | доборы и окно замедляют прогон | добор только при отсутствии; повторы отдельно; маркеры в журнале |
| «Свежий» снимок — заглушка сайта | пользователь видит не то, что ожидал | год снимка в отчёте, счётчики свежести |
| Эвристика «пустой страницы» | ложное срабатывание на коротких страницах | порог настраиваемый, случай виден в журнале |
| Добор по ссылкам раздувает прогон | много запросов на сайте с битыми ссылками | предел 500, один проход, отключается |
| Смена поведения по умолчанию | прежние результаты не воспроизводятся | `--snapshot oldest` = 3.4.0 |
| Смешение эпох | страница 2026 со стилем 2019 | осознанно: полнота важнее единой эпохи |

## 16. Открытые вопросы

1. Порог «пустой страницы»: 0 байт (строго) или 256 байт (как предложено)? По умолчанию 256 с
   записью в журнал.
2. Добор по ссылкам по умолчанию включён (500 адресов) или выключен? Предложено включённым.
3. Нужен ли `--as-of` в окне приложения или достаточно командной строки? Предложено только CLI.
