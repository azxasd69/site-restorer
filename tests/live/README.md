# Живые тесты Site Restorer

Здесь лежит матрица прогонов «на реальных машинах»: варианты запуска, варианты
адресов, варианты скачивания, ожидаемые ошибки и действия пользователя.
Юнит-тесты (`cargo test`) проверяют логику; эти сценарии проверяют сборку,
окружение и поведение в чужих системах.

## Стенды

| Код | Система | Что проверяем |
|---|---|---|
| **H** | Windows 11 Pro x64 (хост) | GUI x64, CLI x64, WOW64 для x86 |
| **V** | Windows 10 Pro 19045 **x86** (Hyper-V `WIN10-X86`, 2 vCPU / 3 ГБ) | настоящая 32-битная система, чистая, без VC++ Redist |
| **L** | Ubuntu 24.04 LTS (Hyper-V `perf-test`, 4 vCPU / 4 ГБ, Xvfb) | musl-сборка CLI, glibc-сборка GUI |

## Как запустить

```powershell
# CLI-матрица (группы: start, site, fetch, fail)
pwsh -File tests\live\run-cli-matrix.ps1 `
  -Exe D:\dist\SiteRestorer-windows-x64-cli.exe `
  -Work D:\sr-tests\live -Only start,site,fail -Json

# GUI-проверки на Windows (нет консольного окна, прогон, стоп, докачка)
pwsh -File tests\live\run-gui-matrix.ps1 -Exe D:\dist\SiteRestorer-windows-x64.exe
```

`-Only` принимает названия групп или подстроку имени кейса; `-Json` пишет
`results.json` рядом с `results.csv`. Сеть нужна только кейсам `site`/`fetch`.

## Матрица CLI

| Кейс | Что проверяется |
|---|---|
| `start-version` | `--version` печатает имя и версию, код 0 |
| `start-usage` | `--cli` без адреса — код 2 и подсказка |
| `start-happy` | полный прогон example.com: отчёт, файлы |
| `start-relative-out` | `--out copy-rel` создаётся от рабочей папки |
| `start-out-spaces-cyrillic` | путь с пробелами и кириллицей |
| `start-out-long-path` | длинный вложенный путь |
| `start-workers-clamp` | `--workers 999` не ломает прогон (клампится) |
| `site-with-path` | адрес с путём (`/catalog/`) |
| `site-with-query` | `?utm_source=…` отбрасывается |
| `site-www` | `www.` приводится к домену |
| `site-uppercase` | `HTTPS://RDBZH.RU/` — регистр схемы и хоста |
| `fail-out-is-file` | `--out` указывает на файл: ошибка, файл цел |
| `fail-out-missing-drive` | недоступный диск: ошибка без паники |
| `fail-site-garbage` | «привет мир» отвергается с подсказкой |
| `fail-site-empty-scheme` | `http://` без хоста отвергается |
| `fail-site-no-archive` | домен без снимков: ошибка «нет страниц» |
| `fail-site-not-exists` | несуществующий домен: ошибка без паники |
| `fetch-limit` | `--limit 4` даёт ровно 4 адреса |
| `fetch-rate` | `--rate 1` замедляет прогон |
| `fetch-encoding-koi8` | KOI8-R распознан и перекодирован |
| `fetch-mixed-404` | сайт с отсутствующими в архиве файлами |
| `load-1200-files` | 1200 файлов на одном сайте: устойчивость на объёме, отчёт, отсутствие падений |
| `load-kill-resume` | процесс убит в середине, затем докачка до конца |
| `load-two-processes` | два экземпляра в одну папку: данные и отчёт не теряются |

Нагрузочные кейсы запускаются только по явному указанию группы:
`-Only load`. Обычный прогон (`-Only start,site,fail`) их не трогает.

## Матрица GUI

| Кейс | Что проверяется |
|---|---|
| окно и отсутствие консоли | PE `Subsystem=2`, нет окна класса `ConsoleWindowClass` |
| старт прогона | `SR_AUTOSTART`/`SR_OUT`: доходит до «Готово», отчёт на диске |
| пустой адрес | «Начать» недоступна, прогон не запускается |
| мусор в адресе | адрес не принимается, подсказка остаётся |
| «Остановить» | этап «Остановлено», процесс жив, кнопки разблокированы |
| повторный «Начать» | «уже в папке: N» и докачка до 100 % |
| «Открыть папку» | открывается папка копии |
| смена языка | RU↔EN переключает подписи |
| закрытие окна в прогоне | процесс завершается, копия читается |

## Результаты (11.11.2026, 3.0.6)

| Стенд | CLI-кейсов | Итог | GUI |
|---|---|---|---|
| H (Win11 x64), статический CRT | 17 + 3 | **17/17 + нагрузка** | окно, прогон, стоп, докачка, отчёт |
| V (Win10 x86), статический CRT | 21 | **21/21** | окно, прогон 1/1, «Готово» (нужен Mesa llvmpipe: в ВМ нет OpenGL) |
| L (Ubuntu 24.04), musl | 11 | **10/11** | окно под Xvfb, «Готово» (нужен `libxkbcommon-x11-0`) |

Единственный провал на L — `linux-rate`: веб-архив в этот момент отвечал
503/504, инструмент корректно сделал 3 попытки и завершился с «archive
unavailable». Это не дефект, а проверка устойчивости; при повторном прогоне
кейс проходит.

## Дефекты, найденные именно этими тестами

| # | Найдено на | Дефект | Исправление |
|---|---|---|---|
| 1 | V (Win10 x86) | exe не запускался: код `0xC0000135`, нужен Visual C++ Redistributable | сборка со статическим CRT (`+crt-static`) для windows-таргетов |
| 2 | V | в консоли cp866 русский текст превращался в кракозябры | `SetConsoleOutputCP(65001)` при консольном режиме |
| 3 | H, V | `HTTPS://RDBZH.RU/` не разбирался (регистр схемы) | схема в `hostname_from_url` сравнивается без учёта регистра |
| 4 | V (ВМ без GPU) | GUI молча выходил с кодом 3 при отсутствии OpenGL 2.0+ | окно с объяснением и советом использовать CLI |
| 5 | V | `Start-Process`/`RedirectStandardOutput` терял код возврата | тест-раннер переведён на `System.Diagnostics.Process` |
| 6 | V | скрипт с кириллицей без BOM не компилировался в PowerShell 5.1 | файлы матрицы хранятся с UTF-8 BOM |
| 7 | L | GUI падал: `libxkbcommon-x11.so` не найдена | зависимость задокументирована; в тестовой ВМ установлена |
| 8 | L | сообщение об ошибке CDX печатало номер страницы с нуля | `page + 1` |
| 9 | H (нагрузка) | при `numpages > 1` быстрый запрос CDX не выполнялся вовсе, а постраничный режим у archive.org для части сайтов всегда пуст — инвентарь получал 1 адрес вместо тысяч | быстрый запрос выполняется всегда (3 попытки при 429/5xx), постраничный — только как резерв |

## Нагрузочный прогон

`anekdot.ru`, `--limit 1200` (11.11.2026): инвентарь 17 146 адресов, из них
взято 1200; скачано **1197 из 1200** за **3,7 мин**, объём копии **79 МБ**,
1193 страницы, 75 387 внутренних ссылок. Память не растёт, отчёт собирается,
процесс не падает. Битых ссылок много (72 657) — это норма для сайта, у которого
в архив попало 17 тысяч адресов из сотен тысяч.

Кейс `load-kill-resume` проверяет, что после `kill` остаются только целые файлы
(`.part` не остаётся), а повторный запуск пишет «уже в папке: N» и догоняет остаток.

## Зависимости GUI

- **Windows**: ничего дополнительно (CRT статический). Для ВМ и RDP без
  аппаратного OpenGL нужен программный OpenGL: положить рядом с exe
  `opengl32.dll`, `libgallium_wgl.dll`, `libglapi.dll` из
  [mesa-dist-win](https://github.com/pal1000/mesa-dist-win) (папка `x86` или
  `x64` по разрядности) и задать `GALLIUM_DRIVER=llvmpipe`.
- **Linux**: `libxkbcommon-x11-0`, `libgl1`, `libegl1`; для машины без дисплея —
  `Xvfb` и `import` из ImageMagick для снимков.

## Стенд `perf-test` (Hyper-V)

- Было: 1 vCPU / 992 МБ. Стало (по решению владельца): **4 vCPU / 4 ГБ**,
  снапшот `before-4cpu-4gb-20261110-0409` для отката, базовый `baseline-1`.
- Гость: Ubuntu 24.04.5 LTS, root по ключу `D:\dev\keys\perf_lab_ed25519`
  (профиль `hv-root` в `tools/vps/vps.py`).
- Доступ к экрану: `tools\vm\vm.ps1 -Action shot` работает только для Windows-ВМ;
  для Ubuntu используется `Xvfb :97` + `import -window root`.
- Для GUI поставлены: `xvfb libgl1 libegl1 libxkbcommon0 libxkbcommon-x11-0
  libgl1-mesa-dri imagemagick x11-apps`.
