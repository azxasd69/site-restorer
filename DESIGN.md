## 1. Назначение и область документа

Документ фиксирует техническое решение: из каких частей состоит продукт, как они
взаимодействуют, по каким алгоритмам работают, какие данные хранят и как ведут себя при
отказах. Требования и критерии приёмки — в [TZ.md](TZ.md); здесь их не дублируют, а
показывают способ выполнения.

Документ описывает **действующее решение** версии 3.3.1. Там, где решение расходится с
требованием, стоит ссылка на пункт плана доработок вида `Д-07`; сводка отклонений —
в разделе 12.

## 2. Контекст решения

| Внешний объект | Взаимодействие | Ограничение |
|---|---|---|
| Internet Archive | Чтение индекса снимков и файлов снимка по HTTPS, при сетевой ошибке — по HTTP | Единственный источник; темп ограничивается архивом; рабочая схема запоминается на прогон |
| Файловая система | Чтение и запись в папку результата | Имена и длины ограничены правилами файловой системы |
| Операционная система | Окно, буфер обмена, диалог папки, консоль | Разные наборы API на Windows и Linux |
| Пользователь | Один человек, один прогон за раз | Без прав администратора и без сервера |

Продукт работает локально: серверной части нет, учётных записей нет, исходящие запросы
идут только на адрес архива.

## 3. Технологический стек и его обоснование

| Решение | Что выбрано | Почему | Следствие |
|---|---|---|---|
| Язык | Rust, редакция 2024, тулчейн закреплён | Один самодостаточный бинарник, отсутствие рантайма у пользователя, предсказуемая производительность | Своя реализация того, что в других экосистемах лежит в библиотеках |
| Оконный слой | egui 0.37 на OpenGL (glow) | Нативное окно без тяжёлых зависимостей, рисуется всё само, размер предсказуем | Требуется поддержка OpenGL 2.0; в средах без неё — консольный режим |
| HTTP | ureq 3.5 с пулом соединений, сжатие через flate2 | Синхронная модель проще для пула потоков, TLS не нужен для архива | Свой слой повторов, пауз и ограничения темпа |
| Кодировки | encoding_rs плюс собственный детектор | Нужны кириллические однобайтовые кодировки и оценка качества текста | Свой набор эвристик, 13 тестов |
| Регулярные выражения | regex-lite | Меньше объём бинарника | Ограниченный синтаксис, шаблоны написаны под него |
| punycode | Своя реализация RFC 3492 | Крейт idna тянет ICU4X ради одной функции | Нет нормализации Unicode, проверка формы метки вручную |
| Буфер обмена и диалог папки | Прямые вызовы WinAPI и shell32 | Встроенный путь на Windows не видел буфер другого процесса | Код под Windows, заглушки на других платформах |
| Профиль выпуска | Оптимизация по размеру, LTO, один модуль кодогенерации, отключение раскрутки стека, удаление символов | Размер поставки в пределах норм ТЗ | Сборка дольше, отладка релизной сборки ограничена |

## 4. Архитектура

### 4.1 Слои и компоненты

```
┌──────────────────────────────────────────────────────────────────┐
│ Интерфейс (окно)               Командная строка                  │
│  форма, прогресс, журнал        параметры, вывод, коды возврата   │
└───────────────┬──────────────────────────────┬───────────────────┘
                │ снимки состояния, отмена      │
┌───────────────┴──────────────────────────────┴───────────────────┐
│ Ядро обработки                                                    │
│  инвентаризация → загрузка → сборка → проверка → отчёт            │
└───────┬──────────────┬──────────────┬──────────────┬─────────────┘
        │              │              │              │
┌───────┴──────┐ ┌─────┴──────┐ ┌─────┴──────┐ ┌─────┴────────────┐
│ Слой сети    │ │ Слой путей │ │ Кодировки  │ │ Разбор адреса    │
│ соединения,  │ │ адрес →    │ │ выбор,     │ │ ввод → домен     │
│ повторы, темп│ │ путь, лимиты│ │ UTF-8      │ │ (чистая функция) │
└──────────────┘ └────────────┘ └────────────┘ └──────────────────┘
```

| Компонент | Ответственность | Ключевые ограничения |
|---|---|---|
| Ядро | Пять стадий конвейера, счётчики, события состояния | Не зависит от окна; не читает настройки интерфейса |
| Слой сети | Соединения, перенаправления, повторы, паузы, темп, отмена | Единственная точка исходящих запросов |
| Слой путей | Нормализация адреса, адрес в путь, класс файла, ограничения ФС | Не знает о состоянии прогона |
| Кодировки | Выбор кодировки, декодирование, нормализация документа | Не зависит от сети и файловой системы |
| Разбор адреса | Ввод пользователя в домен, чистка вставки | Чистая функция, без ввода-вывода |
| Интерфейс | Окно, форма, прогресс, журнал, справка, язык | Не выполняет сетевых вызовов в своём потоке |
| Командная строка | Параметры, вывод, коды возврата, подключение к консоли | Не дублирует логику ядра |
| Локализация | Строки интерфейса и сообщения ядра | Один источник строк на два языка |

### 4.2 Конвейер

```
инвентаризация → загрузка → сборка → проверка → отчёт
  2–8 %            10–85 %     86–95 %    95–98 %    100 %
```

| Стадия | Вход | Выход | Идемпотентность |
|---|---|---|---|
| Инвентаризация | Адрес домена | Список адресов с метками снимков, файл инвентаря | Перезаписывает инвентарь |
| Загрузка | Список адресов | Файлы в папке исходников, карта типов содержимого | Пропускает уже полученное |
| Сборка | Папка исходников | Папка копии с относительными ссылками и UTF-8 | Удаляет и пересобирает |
| Проверка | Папка копии | Число страниц, ссылок, битых | Не изменяет данные |
| Отчёт | Счётчики и проверка | Файл отчёта | Перезаписывает |

### 4.3 Модель выполнения

| Поток | Что делает | Частота |
|---|---|---|
| Поток интерфейса | Отрисовка, ввод, опрос канала сообщений | По событиям; при прогоне перерисовка не реже 5 раз в секунду |
| Рабочий поток движка | Последовательный вызов стадий | Один на прогон |
| Пул воркеров | Получение файлов из общей очереди | Число потоков по параметру, по умолчанию 16 |
| Контроллер конкурентности | Пересчёт лимита по скорости и отказам | Каждые 3 секунды |
| Поток прогресса | Публикация снимка состояния | Каждые 300 миллисекунд |

Взаимодействие: воркеры берут задания через атомарный счётчик позиции в очереди, вход в
сеть регулируется семафором с изменяемым лимитом, состояние считывается атомарными
счётчиками, отмена — общим атомарным признаком. Рабочий поток отправляет события в канал,
интерфейс читает его без блокировки.

Отсутствие общих изменяемых структур — осознанное: единственные блокировки защищают
счётчик лимита, карту типов содержимого и таблицу кодировок, все они короткие.

## 5. Подсистемы

### 5.1 Разбор адреса

Порядок обработки:

1. Удаление невидимого мусора: нормализация Unicode, символы нулевой ширины, метка порядка
   байтов, мягкий перенос, неразрывный пробел; типографские кавычки и тире приводятся к
   простым; строка обрезается по краям.
2. Извлечение адреса из обёртки: ссылка снимка архива (с указанием времени и без него),
   ссылки поисковых систем по параметрам запроса.
3. Прямой разбор: если строка начинается со схемы и не содержит пробелов, берётся имя узла.
4. Иначе строка режется на токены по пробелам и разделителям; из каждого выделяется
   кандидат; берётся первый. Если кандидатов нет, применяется обратное отображение
   раскладки.
5. Приведение домена: нижний регистр, снятие префикса `www`, снятие завершающей точки.
6. Кириллица: если домен верхнего уровня кириллический или латинская форма не проходит
   проверку, домен переводится в punycode; иначе применяется обратное отображение
   ЙЦУКЕН → QWERTY (таблица 32 пар по физическим клавишам).
7. Проверка: метки из букв, цифр и дефиса, длина метки до 63, домена до 253, домен
   верхнего уровня от 2 букв.

Результат — домен и признак источника (`обычный`, `раскладка`, `IDN`), который показывается
пользователю. Функция детерминирована и не имеет побочных эффектов, поэтому проверяется
модульными тестами без сети.

Чистка вставки — отдельный шаг: удаляются управляющие символы, переводы строк сводятся к
пробелам, разметка ссылки вида «текст в скобках» заменяется адресом, снимаются кавычки и
угловые скобки, повторные пробелы сжимаются.

### 5.2 Инвентаризация

| Шаг | Действие | Параметры |
|---|---|---|
| 1 | Пробный запрос числа страниц индекса | Три формата ответа: объект, пары «ключ — значение», число |
| 2 | Быстрый запрос списка адресов | 50 000 адресов за запрос, до 5 попыток; ответ ровно в 50 000 строк считается обрезанным |
| 3 | Постраничный обход до конца либо до предела | По 20 000 записей, предел задаётся `--index-max-pages` (по умолчанию 200), до 5 попыток на страницу; при достижении предела — отметка «индекс неполон» |
| 4 | Нормализация и отбор | Один адрес — одна запись, остаётся самый поздний снимок |
| 5 | Классификация | Страницы, стили и скрипты, изображения, прочее |
| 6 | Запись инвентаря | Сортировка по адресу, ограничение числа адресов по параметру |

Ответ индекса читается порциями по 64 КБ и разбирается собственным парсером: внешний массив
считается контейнером, строка данных начинается с кавычки, служебная строка заголовка
отбрасывается, экранированные символы раскрываются. Пока идёт чтение, каждые 200 мс
публикуются полученный объём, примерное число записей и прошедшее время, поэтому полоса
прогресса на первом этапе двигается, а не стоит. Отказ страницы фиксируется в журнале; если
получен хотя бы один непустой результат, прогон продолжается.

Признак «архив недоступен» выставляется, только если постраничный обход прерван отказом;
отсутствие снимков по адресу — отдельное состояние с другим сообщением.

**Полнота индекса (решение 11.11.2026, ТЗ 4.2.12).** Замеры (см. `docs/index-completeness.md`)
показали три места, где индекс теряется молча: ответ ровно в `limit` строк — это «дальше не просили»,
а не «дальше нет» (на `nginx.org` 50 000 из 70 291); постраничный обход останавливался на 200 страницах,
а у `lenta.ru` их 5 401; `matchType=domain` на крупных доменах отдаёт 504, а 503 приходит и на малых.
Поэтому инвентаризация строится так: явный `matchType` (`domain`, при 504 — `prefix`); ответ, в котором
строк ровно `limit`, считается обрезанным, и обход продолжается по `page` до последней страницы либо до
предела `--index-max-pages` (достижение предела — строка в журнале и отметка «индекс неполон»);
время старта пишется в инвентарь как водяной знак, доборы идут с `from=` от него, итоговая сверка —
с `to=`; 429/503/504 и пустое тело повторяются и никогда не означают «снимков нет».

Сверка выполняется в двух окнах, помимо стартового: **при загрузке** — каждые 500 файлов или 120 секунд
запрос от водяного знака, новые адреса сразу в очередь; **при сборке** — цель ссылки, которой нет ни в
копии, ни в очереди, ставится в очередь (в пределах `--rescue-limit`), скачивается, и затронутые страницы
пересобираются. Добор на сборке идёт до проверки ссылок, иначе отчёт зафиксирует битые ссылки, которые
через секунду перестанут быть битыми.


Выбор версии снимка и полнота копии описаны нормативным документом [docs/snapshots.md](docs/snapshots.md):
целевая дата воспроизведения вместо отпечатка из индекса, признание снимка пригодным, добор
к более старым снимкам, дедупликация путей и поддомены. С 3.5.0 действует именно это поведение:
в индекс уходит `fl=timestamp,original,mimetype,statuscode,length`, по умолчанию запрашивается
снимок, ближайший к текущему времени, фактическая дата снимка читается из `Memento-Datetime`
и попадает в журнал сборки и отчёт.

Схема доступа выбирается на прогон: первым идёт шифрованный канал (`https://web.archive.org`),
запасной — открытый (`http://web.archive.org`). При сетевой ошибке схема переключается, а
рабочая запоминается до конца прогона: обратно к отвергнутой схеме программа не возвращается,
пока не начнётся новый прогон. Повторы при отказе идут с нарастающим интервалом: до пяти
попыток на обращение, пауза 5, 10, 20, 40, 80 секунд (5·2^n), каждая пауза видна в журнале.

### 5.3 Сетевой слой

| Свойство | Реализация |
|---|---|
| Соединения | Пул на агент, соединение переиспользуется; после ошибки соединение закрывается |
| Перенаправления | Обрабатываются клиентом; предел требует проверки (см. раздел 12) |
| Сжатие | Принимается и распаковывается прозрачно |
| Таймаут | 180 секунд на запрос целиком |
| Коды ответа | Не считаются ошибкой транспорта: решение принимает ядро |
| Темп | Общий интервал между запросами по параметру; выключен по умолчанию |
| Схема доступа | Шифрованный канал основной, открытый запасной; переключение по сетевой ошибке, одна строка в журнал, рабочая схема держится до конца прогона |
| Пауза | Общая точка времени, до которой запросы не начинаются; выставляется предохранителем |
| Тело | Читается в память целиком |

Приоритет при отказе: повторить с паузой, затем учесть файл как ошибку. Пауза при отказе 429
берётся из указания сервера, иначе растёт с номером попытки. При сетевой ошибке пауза короче
и тоже растёт.

Смена схемы относится ко всем запросам к архиву, а не только к индексу: адрес берётся из одной
точки, поэтому и снимки уходят по той схеме, что принята для индекса. Сообщение в журнал — одно
на прогон («архив: сеть недоступна, переключаюсь на <адрес>»): повторные переключения молчат,
чтобы не забивать журнал.

### 5.4 Конкурентность

Лимит одновременных запросов хранится в семафоре и меняется на ходу.

| Правило | Значение |
|---|---|
| Стартовый лимит | 2 |
| Нижняя граница | 1 |
| Верхняя граница | 24 |
| Число потоков | Параметр 1–64, по умолчанию 16 |
| Окно наблюдения | 3 секунды |
| Рост | +1, если скорость не упала ниже 95 % предыдущей |
| Снижение | −1, если скорость упала ниже 60 % предыдущей |
| Отказ 429 | Лимит делится вдвое |
| Три окна подряд с 429 | Пауза 120 секунд, лимит сбрасывается к 2 |

Смысл: потолок задаёт не канал, а готовность архива отдавать файлы. Алгоритм поднимает лимит,
пока скорость растёт, и режет при первых признаках сопротивления, поэтому на неизвестной
пропускной способности не требует настройки.

### 5.5 Загрузка файлов

1. Очередь строится чередованием классов: страница, стиль или скрипт, изображение, прочее.
   Так все индикаторы по классам растут одновременно.
2. Готовность файла проверяется по наличию и непустому размеру; готовые исключаются из
   очереди и учитываются в счётчиках.
3. Для каждого адреса строится список попыток: снимок из инвентаря, затем текущий год, год
   назад, два года назад. Варианты с тем же годом не дублируются.
4. На адрес даётся до двух попыток на каждый вариант снимка.
5. Успех: код 200, тело длиннее 20 байт и не является служебной страницей архива.
6. Запись: сначала во временное имя, затем переименование; если переименование невозможно,
   копирование с удалением временного файла. Успех фиксируется только после проверки, что
   файл существует и непуст.
7. Тип содержимого ответа сохраняется в карту «путь — тип» и используется при сборке.
8. Если индекс обещал страницу, а первые байты тела дают сигнатуру двоичного файла (PNG, JPEG,
   GIF, PDF и подобные), файл сохраняется по тому же пути — ссылки на него не ломаются, — но
   страницей не считается: растёт отдельный счётчик `foreign`, до трёх примеров пишутся в
   журнал, в отчёт идёт строка «Под видом страницы не страница». Имя файла в копии остаётся
   прежним: переименование по фактическому типу потребовало бы пересчёта ссылок и сознательно
   не делается.

Отдельно различаются три исхода: получено, отсутствует в архиве (404), ошибка. Они попадают
в разные счётчики и по-разному показываются в отчёте.

### 5.6 Сборка копии

| Шаг | Действие |
|---|---|
| 1 | Индексация папки исходников: точные пути, имена файлов, пары «тип кэша — имя», миниатюры; кэш разрешения ссылок на прогон |
| 2 | Чтение журнала сборки; при полном прогоне без журнала — удаление прежней копии своим обходом с префиксом длинных путей |
| 3 | Обход файлов зеркала один раз за прогон; файлы обрабатываются в пуле потоков |
| 4 | Пропуск неизменённых: размер и время изменения совпали с журналом — файл не переписывается, его цели берутся из журнала |
| 5 | Для текстовых: проверка на двоичное содержимое, декодирование, переписывание ссылок, нормализация кодировки, запись в UTF-8; цели ссылок собираются при переписывании |
| 6 | Прогресс каждые 25 файлов, в конце — сводка перекодировки и строка «без изменений N, обновлено M» |
| 7 | Дедупликация по пути копии: из адресов, дающих один файл, остаётся самый свежий снимок, остальные не скачиваются (`path_collisions`) |
| 8 | Запись журнала атомарно (`.part` + переименование); удаление осиротевших файлов только при полном прогоне |
| 9 | Добор по ссылкам до проверки ссылок: цель, которой нет ни в копии, ни в очереди, ставится в очередь в пределах `--rescue-limit`, скачивается, затронутые страницы пересобираются (ТЗ ФТ-153) |
| 9 | Обход дерева берёт тип записи из каталога (`DirEntry::file_type`), без `stat` на файл: 5394 файла обходятся за 0,3 с вместо 3,5 |
| 10 | Список файлов зеркала и копии снимается один раз за прогон и переиспользуется уборкой, сборкой, проверкой и отчётом |
| 11 | Переписывание ссылок идёт движком `regex` (DFA), а не `regex-lite`: 125–274 МБ/с против 3,3 МБ/с на шаблонах этого проекта |
| 12 | Цели ссылок живут в `Arc<Vec<String>>`: журнал и проверка делят один список, копий нет |

Журнал сборки (`data/build.jsonl`): первая строка — метка `#journal <формат> <версия> <хост> <режим> <окно>`,
дальше по строке на файл: путь относительно зеркала, размер, время изменения, признак страницы,
признак «под видом страницы не страница», дата снимка, время проверки, цели ссылок относительно
корня копии. Метка версии
и хоста защищает от устаревших записей: после обновления программы или смены сайта журнал
не применяется и копия собирается заново.

Число потоков — по числу ядер, не больше 32; переопределяется параметром `--threads`. Каталоги
копии создаются один раз на каталог (кэш каталогов), ошибки записи попадают в журнал работы.

Правила разрешения ссылок, по убыванию надёжности:

1. Точный путь в копии.
2. Кэш движка: файл того же типа с тем же именем, но другим хэшем каталога.
3. Миниатюра вместо оригинала: путь миниатюры приводится к пути оригинала.
4. Оригинал вместо миниатюры: если сохранена только уменьшенная копия.
5. Файл с тем же именем на той же глубине пути.

Переписываются атрибуты адреса, источника, отложенного источника, фона, постера, действия
формы и исходного изображения — в двойных, одинарных кавычках и без кавычек; наборы
источников изображений с сохранением дескрипторов; ссылки в стилях, включая встроенные.
Тег базового адреса удаляется. В скриптах абсолютные адреса своего домена заменяются
корневым путём. Ссылки на якоря, почту, телефон, сценарии и встроенные данные не меняются.

### 5.7 Кодировки

Порядок принятия решения:

| Шаг | Признак | Действие |
|---|---|---|
| 1 | Метка порядка байтов UTF-8, UTF-16LE, UTF-16BE | Декодировать соответствующей кодировкой, метку снять |
| 2 | Тело является корректным UTF-8 | Проверить на двойное кодирование; если признаков нет — принять UTF-8 |
| 3 | Признаки двойного кодирования | Перекодировать обратно через windows-1251, KOI8-R, windows-1252 и выбрать лучший по качеству текста |
| 4 | Объявление кодировки | Заголовок ответа, затем объявление XML, мета-тег, директива стилей — после маскирования комментариев и скриптов, в первых 64 КБ |
| 5 | Статистическая оценка | Перебор шести кандидатов, выбор по качеству текста |

Качество текста — величина от 0 до 1: доля «хороших» символов (кириллица, пробелы, типографика,
латиница, пунктуация) минус штрафы за управляющие символы, символы замены и латиницу с
диакритикой, смешанная с близостью частот букв к русскому языку через критерий хи-квадрат по
33 буквам. Объявлению даётся небольшой бонус, но не абсолютный приоритет: заголовки архива
регулярно не соответствуют телу. Если лучший вариант не дотягивает до порога, берётся
windows-1251 с низкой уверенностью.

Двоичное содержимое определяется по сигнатурам (JPEG, PNG, GIF, PDF, ZIP, WOFF, WOFF2, RIFF,
gzip, BMP, PE, ELF), наличию нулевого байта и доле управляющих символов выше 8 %. Такие файлы
копируются без обработки.

После декодирования все объявления кодировки приводятся к UTF-8; если объявление оказалось
глубже первых 1024 байт (браузер дальше не смотрит), сразу после начала раздела заголовка
вставляется объявление UTF-8.

### 5.8 Проверка ссылок

Проверка не читает страницы второй раз: цели собираются на этапе сборки, в момент переписывания
ссылки (учитывается итоговое, уже локальное значение), и складываются в журнал прогона. На
проверке строится множество известных путей копии (один обход) и считается, сколько целей в
нём нет и сколько целей указывают на каталог с `index.html`.

Правила отбора те же, что были у отдельной проверки: пропускаются внешние адреса и особые
схемы; отбрасываются значения с пробелами и символами `(){},;'"*`` и значения с якорем;
некавычные атрибуты в счёт не идут. Процентные последовательности раскодируются, параметры и
якорь отбрасываются, каталог без имени файла превращается в `index.html`.

### 5.9 Отчёт

Самодостаточный HTML: пять плиток (получено, покрытие, объём, страниц, файлов в копии), таблица
по классам файлов, блок целостности (внутренние ссылки, битые, перекодировка, отказы 404, ошибки
загрузки, файлов в зеркале, уникальных путей в инвентаре, под видом страницы не страница),
предупреждение о статичности копии. Подписи подставляются по языку интерфейса, документ
объявляет соответствующий язык. Объём считается обходом готовой копии, а не счётчиком сеанса,
иначе после докачки он занижен.

Скачанных адресов может быть больше, чем файлов: разные адреса (варианты с параметрами, повторы)
ведут на один файл и перезаписывают тот же путь. Потому отчёт показывает и адреса, и файлы, и
объясняет разницу отдельным абзацем: в копию попадают файлы, на которые ссылаются страницы,
остальные остаются в папке `mirror`.

### 5.10 Интерфейс

| Область | Содержимое |
|---|---|
| Шапка | Заголовок, подзаголовок, поле адреса с подсказкой разбора, поле папки с кнопкой выбора и кнопкой разбора, кнопки запуска, остановки, открытия папки, справки, переключатель языка |
| Карточка прогресса | Этап с индикатором, процент, полоса, последовательность пяти этапов, четыре плитки показателей, сетка два на два по классам файлов |
| Журнал | Тёмная панель, метка времени у каждой строки, уровни сообщений цветом, обрезка строк с показом полного текста, прокрутка к последнему |
| Строка показателей | Под плитками: файлы в секунду (только полученные в этом прогоне), объём, остаток паузы |
| Пустое состояние | Пояснение до первого запуска вместо нулевых полос |
| Справка | Отдельное окно с описанием работы, форматов адреса, структуры папки и параметров |
| Нижняя полоса | Самая нижняя строка окна на всю ширину: справа две ссылки — сайт продукта и «Сказать спасибо»; акцентный цвет, подчёркивание при наведении, подсказка с адресом. Открываются браузером по умолчанию только по клику; неудача открытия — предупреждение в журнале |
| Заголовок окна | «Site Restorer v<версия> — <подзаголовок языка>»: номер подставляется из версии сборки, поэтому совпадает с `--version` |

Ввод: фокус в поле адреса при открытии; разбор по паузе 0,4 секунды, при уходе фокуса, по
Enter (одновременно запускает прогон) и по кнопке; Esc снимает фокус. Вставка поддерживает
основное сочетание, сочетание с Shift, Shift+Insert и среднюю кнопку мыши; на Windows буфер
читается и пишется напрямую через системный интерфейс, потому что встроенный путь не видел
буфер другого процесса.

Состояния окна: готов, инвентаризация, загрузка, сборка, проверка, отчёт, готово, остановлено,
ошибка. В прогоне поля и кнопка запуска заблокированы, кнопка остановки активна.

### 5.11 Командная строка и консоль

Параметры: адрес, папка результата, число потоков, ограничение темпа, ограничение числа
адресов, язык; отдельный параметр печати версии. Значения по умолчанию: папка в профиле
пользователя, 16 потоков, без ограничения темпа, русский язык.

Коды возврата: 0 — успех, 1 — ошибка прогона, 2 — неверные параметры, 130 — остановка
пользователем, 3 — невозможность открыть окно. По завершении печатается строка `RESULT {…}`
с тем же итогом в JSON — для разбора скриптом; человекочитаемая сводка остаётся.

Поля строки `RESULT`: `ok` (скачано адресов), `total` (адресов в инвентаре), `files` (файлов
в копии), `mirror` (файлов в зеркале), `unique` (уникальных путей в инвентаре), `pages`,
`foreign`, `refs`, `broken`, `site`, `report`. Имена и порядок фиксированы: скрипт разбирает
строку по ключам, а не по позиции.

Строки прогресса и сообщения журнала сбрасывают буфер вывода сразу после записи: при
перенаправлении в файл журнал растёт во время работы, а не появляется при завершении процесса.

У оконной сборки консоли нет, поэтому при запуске в режиме командной строки процесс
подключается к консоли родителя, но только если вывод не перенаправлен в файл или канал, и
переключает кодовую страницу на UTF-8. Иначе вывод молча пропал бы.

### 5.12 Иконки и упаковка

Знак продукта задан одним мастер-файлом `packaging/icons/site-restorer.svg` (512×512: тёмный
скруглённый квадрат #2D3748, три белых квадрата 2×2, четвёртый — по пунктиру #9FB0C2).
Отдельных рисунков под платформы нет: `scripts/make-icons.py` (Pillow) разворачивает мастер
в набор PNG 16…512, в `site-restorer.ico` (16–256) и в сырой RGBA 64×64 (`site-restorer-64.rgba`).

Окно получает иконку через `ViewportBuilder::with_icon`: RGBA читается `include_bytes!`, поэтому
декодера PNG в рантайме нет. `build.rs` при наличии `rc.exe` из Windows SDK собирает ресурс
Windows из `packaging/windows/site-restorer.rc.in`: ICON и VERSIONINFO (FileVersion и
ProductVersion из `Cargo.toml`, FileDescription, LegalCopyright MIT). Пути передаются в коротком
формате 8.3 — иначе `rc.exe` не принимает кириллицу в профиле. Нет `rc.exe` — предупреждение,
сборка идёт без ресурса.

Linux: тот же мастер лежит как `packaging/linux/site-restorer.svg` (hicolor/scalable), рядом —
`icons/site-restorer-256.png` для hicolor/256x256; `install.sh` ставит обе, они же попадают в tar.gz.

### 5.13 Просмотр копии встроенным сервером

Решение принято 11.11.2026 по результатам прототипа (ТЗ 4.2.10, план Д-49); в текущей версии не
реализовано.

- **Транспорт.** `tiny_http` 0.12 — синхронный сервер на потоках. Второй рантайм в приложении не
  появляется, дерево зависимостей растёт на четыре крейта, бинарник — примерно на 200 КБ (прототип
  в профиле релиза: 305 152 байта против 108 544 у пустой программы).
- **Модуль.** `src/serve.rs`, около 200–250 строк: `CopyServer::start(site: &Path)`, `url()`, `stop()`.
  Ядро сборки не меняется.
- **Привязка.** Только `127.0.0.1` и порт 0 (выбирает система). Привязка к `0.0.0.0` вызвала бы запрос
  брандмауэра Windows, а доступ из других машин исключён по построению (БЗ-13).
- **Потоки.** Три-четыре воркера на `Server::recv()` из `Arc<Server>`: браузер открывает до шести
  соединений, на больших медиафайлах один поток становится горлышком.
- **Отображение адреса.** Только `paths::url_to_local_path` — та же функция, что при сборке копии.
  Параметры адреса входят в имя файла (`/novosti?PAGEN_1=2` → `novosti__q_c49f0e63/index.html`),
  поэтому готовый раздатчик статики здесь неприменим.
- **Заголовки.** Тип по расширению без параметра `charset` (кодировку задаёт разметка страницы, копии
  бывают в windows-1251), `Accept-Ranges: bytes`, `Cache-Control: no-cache`.
- **Диапазоны.** Ответ 206 с `Content-Range`, запрос за пределом файла — 416, `HEAD` без тела: без этого
  не перематываются видео и PDF в копии.
- **Защита.** Только `GET` и `HEAD`, `canonicalize` с проверкой префикса каталога копии, без листинга
  каталогов; в прототипе `..` и `%2e%2e` дают 404.
- **Завершение.** Флаг остановки, `unblock()` и join при выходе; адрес пишется в журнал одной строкой.
- **Проверено прототипом** на копии `enc-rdbzh`: `/` — 200 (69 546 байт), `/novosti?PAGEN_1=2` — 200
  (55 588 байт, файл с хешем параметров), PDF с кириллицей в имени — 200 (284 289 байт), шесть
  параллельных запросов — 23 мс.

## 7. Обработка отказов

| Ситуация | Поведение | Что видит пользователь |
|---|---|---|
| Отказ 429 на файле | Пауза по указанию сервера или растущая, повтор | Строка «429: пауза N с» |
| Сетевая ошибка | Короткая пауза, повтор, затем учёт в ошибках | Сообщение о сети |
| Файла нет в архиве | Отдельный счётчик | Отчёт: отказы 404 |
| Служебная страница архива | Не сохраняется, считается ошибкой | Сообщение в журнале |
| Отказ архива на индексе | До пяти попыток с паузой 5, 10, 20, 40, 80 с и переключение схемы доступа; после исчерпания — прогон прекращается с отдельным сообщением «archive unavailable» | Строки о паузах и о смене схемы, затем сообщение об отказе архива и совет подождать и повторить |
| Снимков по адресу нет | Прогон прекращается с отдельным сообщением | Рекомендация проверить домен |
| Серия 429 | Пауза 120 с, лимит к 2 | Сообщение о паузе |
| Остановка пользователем | Прекращение за один запрос на любой стадии, паузы повторов не выдерживаются, неполный список адресов не принимается за результат, отчёт не пишется | Этап «Остановлено», кнопки активны, код возврата 130 |
| Ошибка записи файла | Учёт в ошибках, прогон продолжается | Ошибка в журнале, счётчик ошибок |
| Ошибка записи отчёта | Возврат ошибки прогона | Сообщение об ошибке, ненулевой код |
| Нет поддержки графики | Сообщение и выход с отдельным кодом | Объяснение и совет использовать консоль |
| Слишком длинный путь | Детерминированное сокращение, иначе ошибка с понятным текстом | Сообщение «слишком длинный путь» |

Принцип: отказ одного файла никогда не отменяет прогон; отказ источника различается по причине;
пользователь всегда видит, что произошло и что делать.

## 8. Производительность

| Механизм | Что даёт |
|---|---|
| Параллельная загрузка всех классов | Полоса использования канала не проваливается на однотипных файлах |
| Адаптивный лимит | Максимум скорости без блокировки; потолок задаёт архив |
| Чередование очереди | Ранние результаты по всем классам, а не «сначала все страницы» |
| Возобновляемость | Повторный прогон не тратит канал на готовое |
| Однократная индексация копии | Сборка не сканирует диск на каждую ссылку |
| Параллельная сборка (пул потоков) | Время сборки делится на число ядер: замерено ×5 на 400 файлах |
| Один обход дерева зеркала за прогон | В 3.3.1 дерево обходилось восемь раз |
| Кэш каталогов и кэш разрешения ссылок | Повторяющиеся меню и шапки не разрешаются заново |
| Журнал повторного прогона | Неизменённые файлы не пересобираются: замерено ×650 на повторном прогоне |
| Проверка без второго чтения страниц | Этап проверки слит со сборкой, файловая система не опрашивается на каждую ссылку |
| Оптимизация по размеру и LTO | Поставка в пределах норм ТЗ |
| Отсутствие общих изменяемых структур | Нет ожидания на блокировках в горячем пути |

Измерения на контрольных прогонах — в приложении В к ТЗ.

## 9. Безопасность решения

| Граница доверия | Меры |
|---|---|
| Ввод пользователя | Разбор в домен, белый список символов метки, отказ вместо догадки |
| Данные архива | Содержимое не исполняется; имена файлов очищаются, переходы вверх нейтрализуются, служебные имена устройств исключаются, длины ограничены |
| Сеть | Только чтение архива; честное имя клиента; отсутствие обхода защиты |
| Зависимости | Проверки уязвимостей, лицензий, источников и незафиксированных версий на каждой сборке |
| Профиль пользователя | Никаких секретов; настройки ограничены адресом, папкой и языком |
| Целостность поставки | Контрольные суммы, проверка версии, лимиты размера, ссылки сверяются с релизом |

## 10. Ограничения решения и компромиссы

| Компромисс | Причина | Цена |
|---|---|---|
| Нет докачки по частям | Архив отдаёт файл целиком | Обрыв на большом файле — повторная загрузка |
| Индекс читается в память целиком | Простота разбора и сортировки | Пик памяти на очень больших индексах |
| Один прогон за раз | Нет координации папок | Второй экземпляр в ту же папку не блокируется |
| Проверка и отчёт не отменяются | Короткие стадии | Остановка ждёт их завершения |
| Отчёт на одном языке | Шаблон один | Язык отчёта может не совпадать с интерфейсом |
| Встроенного сервера пока нет | Решение принято (5.13), реализация — релиз 3.7.0 (Д-49) | До релиза копию открывают внешним сервером |
| Нет подписи кода | Требует сертификата | Предупреждение системы при первом запуске |
