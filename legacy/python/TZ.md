## 1. Общие сведения

### 1.1 Наименование и обозначение

- Полное наименование: «Site Restorer» — программное средство восстановления
  сайта из веб-архива.
- Краткое обозначение: SR-PY. Версия: 2.4.2.
- Комплект поставки: `SiteRestorer.exe` (GUI, x64), `SiteRestorer-x86.exe`
  (GUI, x86), исходники, документация.

### 1.2 Заказчик, разработчик, пользователи

| Роль | Описание |
|---|---|
| Заказчик | Владелец продукта; формулирует потребность, принимает результат |
| Разработчик | Автор проекта (единственный) |
| Пользователь | Владелец сайта, веб-мастер, подрядчик — один человек за сеанс, без сервера, без прав администратора |

### 1.3 Основание для разработки

Утрата доступа к сайту при наличии снимков в Internet Archive: домен резолвится,
но хостинг не отвечает, резервных копий нет. Существующие инструменты требуют
установки, интерпретатора или постоянно работающего сервера, а штатные средства
архива отдают страницы с панелью и переписанными ссылками, то есть непригодны
для локального просмотра «как было» (кейс `prokupol.ru`, `docs/prokupol-case.md`).

### 1.4 Сроки

Фактические: версии 1.0 → 2.4.2 выпущены 09.11.2026 (по `CHANGELOG.md`).
Документ носит ретроспективный характер, плановые сроки не нормируются.

### 1.5 Порядок оформления и предъявления результатов

Результат предъявляется как: собранный exe (сборка `build.ps1`), прогон на
реальном адресе с отчётом `report.html`, комплект документации, публикация
релиза по тегу (`publish.ps1`, CI).

## 2. Назначение и цели создания

### 2.1 Назначение

По адресу сайта построить локальную статическую копию, пригодную для просмотра
без исходного хостинга, и отчёт о полноте этой копии — без установки зависимостей,
без прав администратора, одним запуском.

### 2.2 Цели и проверяемые признаки

| ID | Цель | Проверяемый признак | Чем подтверждается |
|---|---|---|---|
| Ц-1 | Копия открывается локально и выглядит как оригинал | Страницы, стили, картинки отдаются из папки `site` при запуске любого локального сервера | Кейс `prokupol.ru`: 315 МБ, 1164 из 1168 HTML, каталог 1042 из 1044 |
| Ц-2 | Работает на любом сайте, сохранившемся в архиве | Успешные прогоны на разных CMS без настройки под движок | `ARCHITECTURE.md` §4: Bitrix, WordPress, MODX, Craft, Laravel |
| Ц-3 | Пользователь видит, что происходит | Прогресс по этапам, по типам файлов, скорость, потоки, ETA, журнал | `main.py → poll`, `core.py → Engine._snapshot` |
| Ц-4 | Архив не блокирует за высокую нагрузку | Серия 429 приводит к снижению потоков, паузе и продолжению с того же места | `core.py → Engine._controller` |
| Ц-5 | Прерванный прогон продолжается, а не начинается заново | Повторный запуск не скачивает готовые файлы | `core.py → Engine.download` (пропуск файлов с размером > 0) |
| Ц-6 | Понятно, чего в копии нет | Отчёт: покрытие, разбивка по типам, битые ссылки, отсутствующие в архиве | `core.py → Engine.report`, `report.html` |
| Ц-7 | Ноль зависимостей и установки | Один exe, только стандартная библиотека | `build.ps1` (PyInstaller, stdlib), `ARCHITECTURE.md` §5 |

### 2.3 Что не входит в цели

| Не делается | Причина |
|---|---|
| Обход капчи, подмена User-Agent под браузер, ротация IP | Провоцирует блокировку «suspected abusive bot traffic»; сознательный отказ |
| Восстановление динамики: корзина, авторизация, поиск, AJAX-фильтры | В архиве нет серверной части; вне статической копии |
| Хостинг, публикация, деплой копии | Пользователь поднимает локальный сервер сам |
| Встроенный веб-сервер | Отдельная задача; в 2.x отсутствует (Приложение Б) |
| Работа с платными API и любыми внешними сервисами | Продукт не должен зависеть от чужого биллинга |
| Докачка больших файлов по HTTP Range | Архив отдаёт целые ответы; ценность ниже стоимости |

## 3. Характеристика объекта автоматизации

### 3.1 Источник данных: CDX API Internet Archive

Взаимодействие идёт только с двумя точками: `http://web.archive.org/cdx/search/cdx`
(индекс) и `/web/<метка>id_/<адрес>` (сами байты снимка).

| Параметр / поведение | Значение в реализации |
|---|---|
| Отбор записей | `matchType=domain`, `filter=statuscode:200`, `collapse=urlkey` |
| Поля ответа | `timestamp, original, mimetype, statuscode` |
| Оценка объёма | пробный запрос `showNumPages=true&output=json`; поддерживаются три формата ответа: `{"pages":N}`, `[["numpages"],["N"]]`, просто `N` |
| Один запрос (малый сайт) | `limit=50000` |
| Постраничный обход | по `20000` записей на страницу, не более `min(pages, 200)` страниц |
| Резервный обход | если быстрый запрос не дал записей — `5000` на страницу, до `200` страниц |
| Признаки усечения | предупреждение при `≥ 50 000` адресов и при `> 200` страниц |
| Отказ источника | `HTTP 429/500/502/503/504` → пауза `Retry-After` или `10 + 15×попытка` с, до 3 попыток на страницу |

Ограничения источника приняты как внешние: количественные квоты архив не
публикует, поэтому инструмент работает «вежливо» и адаптивно (§ 4.2.4, ФТ-20…ФТ-26).

### 3.2 Классы восстанавливаемых сайтов

| Класс | Что важно для алгоритма |
|---|---|
| Статические сайты | Абсолютные и относительные ссылки, `srcset`, CSS `url()` |
| Bitrix (в т. ч. шаблоны Aspro) | Кэш с хэшем в имени: `bitrix/cache/css/s1/<шаблон>/<файл>_<hash>_v1.css`; миниатюры `upload/resize_cache/iblock/...` |
| WordPress, MODX | Параметры версии в ссылках (`?ver=`), минифицированные файлы |
| Craft, Laravel | Крупные индексы (тысячи URL), много типов файлов |

Различия движков на конвейер не влияют: инструмент работает с архивными URL,
а не с CMS; эвристики применяются только как разрешение «файла нет по точному пути».

### 3.3 Пользователь и условия работы

Один пользователь, Windows 10/11, права обычного пользователя, домашний интернет
(порядка 10 Мбит/с в расчётах `ARCHITECTURE.md` §1.3), копия на локальном диске.
Изменение системных настроек не требуется.

### 3.4 Сценарии использования

| ID | Сценарий |
|---|---|
| С-1 | Пользователь вставляет адрес (или ссылку из архива/поиска), запускает, видит прогресс, получает папку `site` и `report.html` |
| С-2 | Прогон прерван (закрытие окна, обрыв сети, лимит архива) — повторный запуск продолжает с места остановки |
| С-3 | Архив ответил серией 429 — инструмент снижает потоки, ждёт, продолжает без вмешательства |
| С-4 | Нужен автоматический прогон — запуск через CLI с параметрами и машиночитаемым результатом |

## 4. Требования к системе

### 4.1 Требования к структуре системы

**Обязательно.** Система состоит из трёх модулей и набора тестов; конвейер
обработки — пять последовательных стадий.

| Модуль | Строк | Ответственность | Запрещено |
|---|---|---|---|
| `core.py` | 1122 | конвейер, сеть, сборка, проверка, отчёт | импортировать tkinter и читать конфигурацию самостоятельно |
| `main.py` | 811 | GUI, CLI, конфигурация, локализация, упаковка путей | выполнять сетевые операции в потоке интерфейса |
| `sanitize.py` | 214 | разбор адреса сайта | ходить в сеть, читать файлы |
| `tests/` | 185 | 17 тестов без сети | зависеть от доступности архива |

**Стадии конвейера** (`core.py → Engine.run`): инвентаризация → загрузка →
сборка → проверка → отчёт. Каждая стадия идемпотентна по отношению к своему
результату: повторный запуск переиспользует `mirror/`, пересобирает `site/`.

**Схема выходного каталога** (обязательно, это контракт для пользователя):

```
<папка>\
  mirror\          — сырые файлы из архива, как отдал сервер
  site\            — готовая копия (её и открывают)
  data\inventory.jsonl — инвентарь: url, ts, orig, mime, path, type (по строке на URL)
  report.html      — отчёт о полноте
```

### 4.2 Требования к функциям

#### 4.2.1 Ввод и нормализация адреса

| ID | Требование | Критерий приёмки | Реализация |
|---|---|---|---|
| ФТ-01 | Принимать адрес в любом виде: с схемой и без, с путём, портом, якорем, в кавычках, в тексте, в верхнем регистре, с завершающей точкой | Из каждой формы получается один и тот же домен | `sanitize.py → sanitize_site`, тест `test_sanitize.test_cases` |
| ФТ-02 | Удалять невидимый мусор копипаста: NFKC, zero-width, BOM, мягкий перенос, неразрывный пробел, типографские кавычки и тире | Адрес, скопированный из мессенджера или документа, распознаётся | `sanitize.py → _strip_invisible` |
| ФТ-03 | Распознавать ссылки-обёртки: `web.archive.org/web/<ts>/<url>`, `google.com/url?q=`, `yandex…?url=`, `bing`, `duckduckgo` | Возвращается исходный домен, а не домен поисковика | `sanitize.py → _from_redirect` |
| ФТ-04 | Различать две причины кириллицы: текст, набранный в русской раскладке (обратное отображение ЙЦУКЕН→QWERTY), и настоящий IDN-домен (punycode) | `зкщлгзщдюкг → prokupol.ru`; `прокупол.рф → xn--…` | `sanitize.py → _dekeyboard`, `_idna`, `_finish`; тест `test_idn` |
| ФТ-05 | Отклонять вход, из которого нельзя получить домен: пустая строка, слово без точки, только схема | Возвращается `None` и ключ ошибки; интерфейс показывает предупреждение | `sanitize.py`, тест `test_rejects_garbage`; `main.py → normalize_field` |
| ФТ-06 | Нормализовать адрес в поле ввода на месте: при вставке, при уходе фокуса, при Enter | Поле показывает домен, подсказка — «→ домен» | `main.py → normalize_field`, `paste_normalize` |

|---|---|---|---|

### 5.2 Программное обеспечение

| Компонент | Требование |
|---|---|
| Язык и рантайм | Python 3.14 (сборка: `py -3.14` / `py -3.14-32`) |
| Библиотеки | только стандартная: `http.client`, `urllib`, `json`, `threading`, `queue`, `tkinter`, `hashlib`, `gzip`, `zlib`, `unicodedata`, `re`, `shutil`, `argparse`, `ctypes` |
| Упаковка | PyInstaller 6.22.3, `--onefile --windowed --icon`, ресурс `app.ico` включается в сборку |
| Сборка | `build.ps1` создаёт `.venv` / `.venv32`, ставит PyInstaller, собирает x64 и (по `-Both`) x86 |
| Лицензия | MIT; сторонних компонентов с иными лицензиями нет |

### 5.3 Лингвистическое обеспечение

- Два языка интерфейса: русский (по умолчанию) и английский; 38 ключей на язык.
- Термины: «инвентаризация», «снимок», «копия», «сборка», «покрытие», «потоки».
- Форматирование: русская локаль — десятичная запятая, единицы «Б / КБ / МБ», время «мин с»; английская — точка и «B / KB / MB», «s».
- Сообщения об ошибках — на языке интерфейса, с действием («подождите», «проверьте домен»).

### 5.4 Техническое обеспечение

Персональный компьютер под Windows 10/11, x64 или x86; свободное место — не менее
двух объёмов копии (`mirror` + `site`); оперативная память — достаточная для
интерфейса и потоковой обработки индекса (специальных требований не предъявляется);
сеть — доступ к `web.archive.org` по HTTP/HTTPS.

### 5.5 Организационное обеспечение

Порядок выпуска версии: правка кода → прогон тестов → сборка `build.ps1` →
проверка на реальном адресе → запись в `CHANGELOG.md` → коммит и тег →
публикация релиза (`publish.ps1`, CI). Роли: разработчик и приёмщик — одно лицо;
приёмка фиксируется прогоном и отчётом.

### 5.6 Метрологическое обеспечение

Измерения носят прикладной характер (время, объём, число файлов, число 429).
Средства контроля: 17 модульных тестов, прогоны на пяти CMS, приёмочный кейс
`prokupol.ru`. Погрешности не нормируются.

### 8.1 Критерии приёмки

| ID | Критерий | Способ проверки | Результат на 2.4.2 |
|---|---|---|---|
| ПРМ-1 | Все модульные тесты проходят | `python -m unittest discover -s tests` | 17 из 17, OK (0,2 с) |
| ПРМ-2 | Копия реального сайта собирается и открывается | прогон на сайтах разных CMS | по журналу проекта собраны все 5; кейс `prokupol.ru`: 1609 из 1638 URL (98,2 %) |
| ПРМ-3 | Отчёт соответствует фактам | сверка чисел отчёта с содержимым `site/` | совпадает (HTML 1164/1168, каталог 1042/1044) |

| ПРМ-5 | Серия 429 не роняет прогон | наблюдение в часы нагрузки архива | по журналу проекта: потоки снижаются, пауза, продолжение |
| ПРМ-6 | Интерфейс не блокируется во время работы | прогон + переключение языка, клики | поток-исполнитель и очередь событий: интерфейс отвечает; язык переключается на лету |

### 8.2 Что считается дефектом

- Неверная кодировка текста в копии или «кракозябры».
- Ссылка в копии ведёт на абсолютный адрес исходного домена.
- Файл, присутствующий в архиве, отсутствует в `mirror/` без записи в «ошибки».
- Падение приложения вместо сообщения при отказе архива.
- Расхождение чисел в `report.html` с фактическим содержимым `site/`.

## Приложение Б. Пробелы и слабые места (не выданы за требования)

| № | Что не сделано / сделано частично | Последствие | Приоритет |

| Б-2 | Инвентарь усечён 50 000 адресов и 200 страницами CDX | крупные сайты копируются частично, есть только предупреждение | средний |
| Б-3 | `verify` проверяет только ссылки из HTML; ссылки внутри CSS/JS не проверяются | часть битых ресурсов не видна в отчёте | средний |
| Б-4 | Нет журнала в файл: диагностика только в окне и в stdout | после закрытия окна история теряется, поддержка затруднена | высокий |
| Б-5 | AIMD не покрыт тестами (только наблюдение) | регрессия в регулировании может остаться незамеченной | высокий |
| Б-6 | Распознавание заглушек архива — по трём текстовым маркерам | при смене текста заглушки в копию попадёт «пустая страница» | средний |

## Приложение В. Словарь терминов

| Термин | Значение |
|---|---|
| CDX | индексный API Internet Archive со списком снимков по адресам |
| Снимок (snapshot) | сохранённая копия страницы на определённую дату, адресуется меткой времени |
| `id_` | режим отдачи снимка «как есть», без панели архива и переписывания ссылок |
| Инвентаризация | получение списка адресов и выбор самого свежего снимка для каждого |
| `mirror/` | сырые файлы из архива |
| `site/` | собранная копия с относительными ссылками и UTF-8 |
| Покрытие | доля скачанных файлов от числа адресов в инвентаре |
| AIMD | additive increase / multiplicative decrease — алгоритм подбора конкурентности |
| 429 | ответ «слишком много запросов»; источник просит снизить темп |
| Заглушка архива | страница-ответ «этого снимка нет», которую нельзя сохранять как контент |

## Приложение Г. Как это решено в Rust-версии 3.x

| Тема | Python 2.4.2 | Rust 3.x |
|---|---|---|
| Носитель | PyInstaller-сборка, Python внутри | один самодостаточный бинарник, без рантайма |
| Интерфейс | tkinter/ttk | egui/eframe, свой слой буфера обмена на WinAPI |
| Зависимости | stdlib only | 4 прямые зависимости, свой punycode (RFC 3492) |
| Кодировки | объявление + перебор кандидатов | перебор кандидатов по качеству текста (без `chardetng`) |
| Тесты | 17 | 50 (`cargo nextest`), плюс clippy/audit/deny/machete/typos |
| Буфер обмена | системный ввод tkinter | `src/clip.rs`: `OpenClipboard`/`GetClipboardData` (arboard не читал чужой буфер) |
| Регулирование потоков | AIMD с тактом 3 с | поведение и параметры — по `ARCHITECTURE.md` текущей ветки |
| Поставка | отдельные exe x64/x86 | единая схема имён `SiteRestorer-<os>-<arch>`, релиз из 8 файлов |

Часть пробелов Приложения Б в 3.x закрыта: тестов 50 вместо 17, добавлены линтеры
и проверки зависимостей, журнал подробнее. Докачка по HTTP Range и встроенный
локальный сервер в требования 3.x на момент 3.1.3 не входили — то есть эти
пункты Приложения Б остаются открытыми и для новой ветки.
