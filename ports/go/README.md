# site-restorer-go

> **Архив.** Порт на Go больше не разрабатывается, не собирается в CI
> и не попадает в релизы. Актуальная реализация — Rust в корне репозитория
> (`src/`, окно egui + CLI). Код оставлен как история.

Независимая реализация утилиты Site Restorer на Go: восстанавливает копию сайта из веб-архива
(`web.archive.org`) и собирает её в автономную папку с относительными ссылками.

Только стандартная библиотека Go — внешних зависимостей нет, `go.mod` без `require`.
Punycode (RFC 3492) реализован вручную, декодирование windows-1251 — таблицей.

## Сборка и тесты

# Windows-шелл: go берём из D:\dev\go
D:\dev\go\bin\go.exe test ./...
D:\dev\go\bin\go.exe vet ./...

## Запуск

```bash
site-restorer-go --cli --site example.com --out /tmp/sr-go-out --limit 5
site-restorer-go --sanitize "Сайт: prokupol.ru — магазин"
site-restorer-go --cli --site prokupol.ru --out ./out --stage inventory
```

Флаги:

| флаг | смысл |
|---|---|
| `--cli` | режим командной строки: полный конвейер (фактически работает всегда, когда задан `--site`) |
| `--site <адрес>` | адрес в любом виде; без него печатается справка и код возврата 2 |
| `--out <папка>` | папка результата, по умолчанию `sr-out` |
| `--limit N` | сколько адресов брать из инвентаря CDX (0 — все) |
| `--workers N` / `--max-workers N` | стартовая конкурентность загрузки (2) / потолок AIMD (24) |
| `--pages N` | потолок постраничного обхода CDX (200) |
| `--stage all\|inventory\|download\|build\|verify` | остановиться после этапа (неизвестное значение — как `all`) |
| `--sanitize "<текст>"` | только разобрать адрес и выйти: `<домен>\t<как распознан>` |
| `--cdx <url>` | подмена адреса CDX API |
| `--archive <url>` | подмена адреса веб-архива для загрузки |

Коды возврата: 0 — успех, 2 — не разобран адрес или нет `--site`, 3 — сбой этапа.

Проверено 09.11.2026: `--cli --site example.com --out C:\Temp\go-out --limit 5` → инвентарь 2 адреса
(оба сошлись в `index.html`), скачан 1 файл (438 Б), `report.html` создан, битых ссылок 0.

Результат в `--out`:

```
mirror/            снимки как пришли из архива (id_-режим)
site/              копия с относительными ссылками и UTF-8
inventory.json     инвентарь CDX
download.json      что скачано, что отсутствует, что упало
report.html        отчёт: покрытие, размер, типы, битые ссылки
run.log            журнал прогона
```

## Что внутри

### 1. Разбор адреса — `internal/host`

`sanitize` понимает: URL со схемой и без, путь/порт/завершающую точку, текст вокруг
(«Сайт: prokupol.ru — магазин»), ссылку веб-архива (`/web/<ts>/...`, в том числе `id_`),
редирект поисковика (`google.com/url?q=...`), адрес в русской раскладке
(`зкщлгзщдюкг` → `prokupol.ru`), кириллический IDN (`прокупол.рф` → `xn--j1achbcce0a.xn--p1ai`).
Мусор без точки (`prokupol`), пустая строка и битые схемы отвергаются (код возврата 2).

Раскладка и IDN различаются по зоне: если последняя метка — кириллический TLD (`рф`, `укр`, …),
ввод трактуется как IDN; иначе проверяется вариант после перекладки на QWERTY и его зона
(`ru`, `com`, …). Punycode — собственная реализация RFC 3492 (`internal/host/punycode.go`).

### 2. Пути — `internal/localpath`

URL → относительный путь, детерминированно:

- `/` и `.../` → `index.html`; путь без расширения → `<сегмент>/index.html`;
- query-строка → суффикс `-q<fnv1a-hex8>` перед расширением (`page.php?id=3` → `page-q1a2b3c4.php`);
- запрещённые в Windows символы (`< > : " \ | ? *`), пробел, `~` и все не-ASCII байты
  экранируются как `~XX` — имена остаются ASCII и переносимыми;
- зарезервированные имена (`CON`, `PRN`, `AUX`, `NUL`, `COM1-9`, `LPT1-9`) получают префикс `_`;
- `..` и `.` нейтрализуются в `_`, обход каталога невозможен (в том числе через `%2e%2e%2f`);
- относительный путь ≤ 160 байт, сегмент ≤ 63 байт: длинные сегменты сжимаются с хэшем,
  сверхдлинный путь уходит в `_long/<hash8><ext>`.

Файлы чужих доменов (CDN, `www` не считается чужим) лежат в `_ext/<хост>/...`.

### 3. Инвентарь — `internal/inventory`

CDX API: пробный `showNumPages=true&output=json`, затем один запрос
(`collapse=urlkey&limit=50000`, поля `timestamp,original,mimetype,statuscode`,
`filter=statuscode:200`). Если общий запрос упёрся в лимит или упал (на больших доменах
archive.org отдаёт 504) — постраничный обход `&page=i` до `--pages` (200). Дубликаты
схлопываются по нормализованному URL (схема/порт/фрагмент), остаётся самый свежий снимок.

### 4. Загрузка — `internal/downloader`

`http://web.archive.org/web/<timestamp>id_/<original>`, запись через `.part` + переименование,
файл считается готовым, если существует и непустой (докачка при повторном запуске).

Конкурентность AIMD: старт 2, +1 каждые 3 с при прогрессе, при 429 — вдвое меньше,
три 429 подряд → пауза 120 с и сброс к 2, потолок 24. `Retry-After` соблюдается.
404 → «нет в архиве» (не ошибка), затем пробуются соседние годы (текущий, −1, −2);
сетевые ошибки и 5xx — повторы с ростом паузы, затем статус `error`.

### 5. Сборка — `internal/assemble`

`mirror` → `site`: ссылки своего домена (и скачанных внешних) переписываются в относительные.
Обрабатываются атрибуты `href src data-src data-bg poster action data-original`
(в кавычках и без), `srcset`/`data-srcset`, `url(...)` в CSS и inline-стилях, теги `<base>`
удаляются. HTML/CSS декодируются (UTF-8 → объявленная кодировка из `meta charset`/`@charset`
→ windows-1251) и пишутся в UTF-8, объявления кодировки заменяются на `utf-8`.

Эвристики для отсутствующих файлов:

- `bitrix/cache/(css|js)/s1/.../<name>_<hash>_v1.<ext>` → файл того же типа с тем же префиксом
  имени (хэш кэша меняется при регенерации);
- `upload/resize_cache/iblock/<aa>/<size>/<name>` → `upload/iblock/<aa>/<name>`;
- поиск по имени файла при совпадении глубины, затем по имени вообще.

### 6. Проверка и отчёт — `internal/verify`, `internal/report`

Обход HTML в `site/`: считаются внутренние ссылки и битые (нет файла), поддерживаются
одинарные, двойные кавычки и значения без кавычек, `srcset` и `url(...)`.
`report.html` — автономная страница: покрытие (скачано / адресов инвентаря), размер копии,
разбивка по типам (html/css/код и шрифты/изображения/прочее), число битых ссылок и примеры.

## Тесты

`go test ./...` — 24 тестовые функции:

- `internal/host` — все формы адреса, punycode на известных значениях, отказ мусору;
- `internal/localpath` — базовая раскладка, query-суффикс, обход каталога (`..`, `%2e%2e`),
  зарезервированные имена, запрещённые символы, лимит 160/63 байта, не-ASCII, детерминированность;
- `internal/assemble` — переписывание атрибутов (кавычки/без кавычек), `<base>`, srcset,
  inline-стили, CSS, эвристики Bitrix, декодирование windows-1251, относительные пути;
- `internal/inventory` — разбор ответов CDX (оба формата числа страниц, заголовок, мусор),
  нормализация ключей дедупликации;
- `internal/verify` — подсчёт ссылок в одинарных/двойных кавычках и битых ссылок.

## Ограничения

- archive.org нестабилен: 503/504 на общих запросах — штатная ситуация, утилита уходит
  в постраничный обход и повторяет запросы; прогон на «тяжёлом» домене может занять минуты.
- Содержимое `site/` не переписывается в JS-строках и JSON внутри страниц — только атрибуты,
  CSS и inline-стили.
- Часть ссылок остаётся битой, если файла нет в архиве или он за пределами `--limit`;
  такие ссылки видны в отчёте.
