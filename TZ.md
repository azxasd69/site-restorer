## 1. Общие сведения

### 1.1 Наименование и обозначение

- Полное наименование: «Site Restorer» — средство восстановления сайта из веб-архива.
- Обозначение изделия: SR. Версия: 3.1.3.
- Комплект поставки: исполняемые файлы для Windows (x64, x86) и Linux (x64), архив с обоими
  Linux-бинарниками, установочный сценарий для домашнего каталога, контрольные суммы,
  документация и исходный код.

### 1.2 Заказчик, разработчик, пользователи

| Роль | Описание |
|---|---|
| Заказчик | Владелец продукта; формулирует потребность, принимает результат |
| Разработчик | Автор проекта |
| Пользователь | Владелец сайта, веб-мастер, подрядчик: один человек за сеанс, без сервера, без прав администратора |

### 1.3 Основание для разработки

Утрата доступа к сайту при сохранённых снимках в Internet Archive: домен резолвится, но
хостинг недоступен, резервных копий нет. Штатные средства архива отдают страницы с панелью
навигации и переписанными ссылками, поэтому для локального просмотра в исходном виде они
непригодны. Требуется инструмент, который собирает автономную копию и сообщает, что именно
восстановить не удалось.

Типовой случай: домен на CMS с каталогом товаров, около 1600 адресов в индексе архива,
снимки за десять лет, изображения товаров в архив не попадали.

### 1.4 Плановые сроки и этапы

| Этап | Содержание | Результат этапа |
|---|---|---|
| 1 | Базовый конвейер: инвентаризация, загрузка, сборка, отчёт | Копия сайта по адресу, отчёт о покрытии |
| 2 | Пропускная способность и устойчивость: параллельная загрузка, адаптивная конкурентность, работа с ограничениями архива, возобновляемость | Загрузка большого домена без блокировок и потерь |
| 3 | Ввод, интерфейс, локализация: разбор любого адреса, окно с прогрессом, два языка, справка | Пригодность для пользователя без инструкции |
| 4 | Качество и поставка: кодировки, тесты, живые проверки, релизная схема, документация | Публикуемый релиз с проверяемыми артефактами |

Сроки этапов 1–4: ноябрь 2026. Этапы выполняются последовательно; каждый заканчивается
приёмкой по критериям раздела 8.

### 1.5 Порядок предъявления результатов

Результат этапа предъявляется как: собранный исполняемый файл, прогон на реальном адресе с
отчётом о покрытии, комплект документации. Результат последнего этапа дополнительно
включает публикуемый релиз с контрольными суммами и проверенными ссылками на скачивание.

## 2. Назначение и цели создания

### 2.1 Назначение

По адресу сайта построить локальную статическую копию, пригодную для просмотра без
исходного хостинга, и отчёт о полноте этой копии — без установки зависимостей, без прав
администратора, одним запуском.

### 2.2 Цели и проверяемые признаки

| ID | Цель | Проверяемый признак |
|---|---|---|
| Ц-1 | Копия открывается локально и выглядит как оригинал | Страницы, стили и изображения отдаются из папки копии при запуске любого локального веб-сервера |
| Ц-2 | Работает на любом сайте, сохранившемся в архиве | Успешный прогон на сайтах разных движков без настройки под движок |
| Ц-3 | Пользователь видит, что происходит | Этап, процент, скорость, число потоков, оценка остатка, полосы по типам файлов, журнал |
| Ц-4 | Архив не блокирует за высокую нагрузку | Серия отказов 429 приводит к снижению числа потоков, паузе и продолжению с того же места |
| Ц-5 | Прерванный прогон продолжается, а не начинается заново | Повторный запуск не скачивает уже полученные файлы |
| Ц-6 | Понятно, чего в копии нет | Отчёт: покрытие, объём, разбивка по типам, битые ссылки, отсутствующие в архиве, ошибки загрузки |
| Ц-7 | Ноль зависимостей у пользователя | Один исполняемый файл; интерпретатор и библиотеки не требуются; на чистой системе запускается без дополнительных пакетов |
| Ц-8 | Релиз воспроизводим и проверяем | Версия в артефакте совпадает с тегом, размеры в пределах норм, контрольные суммы, ссылки на скачивание живые |
| Ц-9 | Ввод не требует объяснений | Любая вставка — адрес, ссылка из поиска или архива, набор в русской раскладке, кириллический домен — приводит к корректному домену |

### 2.3 Что не входит в цели

| Не делается | Причина |
|---|---|
| Обход защиты архива: капча, подмена User-Agent под браузер, ротация адресов | Провоцирует блокировку автоматического трафика; сознательный отказ |
| Восстановление динамики: корзина, вход, поиск, фильтры, AJAX | Серверной части в архиве нет |
| Хостинг и публикация копии | Пользователь поднимает локальный сервер самостоятельно |
| Встроенный веб-сервер | Отдельная задача, в границы версии 3.x не входит |
| Работа с платными API и внешними сервисами | Продукт не должен зависеть от чужого биллинга |
| Докачка больших файлов по частям (HTTP Range) | Архив отдаёт файл целиком; выигрыш ниже стоимости |
| Сборки для macOS и 32-битного Linux | Нет контрольной конфигурации и полного набора библиотек |
| Установщик Windows с правами администратора | Продукт портативный; установка не требуется |

## 3. Характеристика объекта автоматизации

### 3.1 Источник данных

Единственный источник — индекс и снимки Internet Archive. Взаимодействие идёт с двумя
точками: индекс снимков домена и выдача конкретного снимка в исходном виде.

| Параметр | Нормативное значение |
|---|---|
| Отбор записей индекса | По домену, только успешные снимки, по одному на адрес |
| Поля ответа индекса | Метка времени, исходный адрес, тип содержимого, код ответа |
| Оценка объёма | Пробный запрос числа страниц индекса; поддерживаются все известные форматы ответа |
| Быстрый запрос списка | Выполняется всегда: до 50 000 адресов за запрос, до трёх попыток |
| Постраничный обход | Только как резерв: по 20 000 записей, не более 200 страниц |
| Поведение при отказе | Пауза по указанию сервера либо выдержка с ростом интервала; до трёх попыток на страницу |
| Выдача снимка | Исходные байты без панели архива и без переписывания ссылок |
| Признаки усечения | Предупреждение при достижении 50 000 адресов и при исчерпании лимита страниц |

Быстрый запрос обязателен независимо от числа страниц: постраничный режим поддерживается не
для всех доменов и у части из них всегда пуст, поэтому опора на число страниц приводит к
неполному инвентарю.

### 3.2 Классы восстанавливаемых сайтов

| Класс | Что важно для алгоритма |
|---|---|
| Статические сайты | Ссылки в двойных, одинарных кавычках и без кавычек, `srcset`, `url()` в стилях, тег `base` |
| Сайты на Bitrix, в том числе с шаблонами Aspro | Кэш с хэшем в имени файла, миниатюры в отдельном дереве каталогов |
| WordPress, MODX | Параметры версии в ссылках, минифицированные файлы |
| Крупные каталоги и блоги | Тысячи адресов, много типов файлов, обрывы на объёме |
| Старые сайты в windows-1251 и KOI8-R | Кодировка объявлена неверно или не объявлена вовсе |

Дополнительные правила подстановки применяются только как разрешение ситуации «файла по
точному пути нет» и не влияют на точные совпадения.

### 3.3 Пользователь и условия работы

Один пользователь, права обычного пользователя, копия на локальном диске, доступ к сети.
Поддерживаемые системы: Windows 10/11 (x64 и x86) и Linux (x64). В виртуальных машинах и
удалённых сеансах без аппаратного ускорения графики окно может не открыться — в этом случае
предусмотрены сообщение с объяснением и работа через командную строку.

### 3.4 Сценарии использования

| ID | Сценарий |
|---|---|
| С-1 | Пользователь вставляет адрес или ссылку, запускает сборку, наблюдает прогресс, получает папку копии и отчёт |
| С-2 | Прогон прерван (закрытие окна, обрыв сети, ограничение архива) — повторный запуск продолжает с места остановки |
| С-3 | Архив отвечает серией отказов 429 — число потоков снижается, выдерживается пауза, работа продолжается без участия пользователя |
| С-4 | Автоматический прогон: запуск из командной строки с параметрами, разбор машинночитаемого итога и кода возврата |
| С-5 | Работа в виртуальной машине без аппаратной графики — окно объясняет причину и предлагает консольную сборку |
| С-6 | Повторный прогон на ту же папку, чтобы добрать файлы, которых не хватило из-за лимита или обрыва |

### 3.5 Контрольные конфигурации

| Конфигурация | Что проверяется |
|---|---|
| Windows 11 x64 | Оконная и консольная сборки x64, совместимость x86 |
| Windows 10 x86, чистая установка без библиотек времени выполнения | Запуск без дополнительных пакетов |
| Linux x64 | Статическая консольная сборка, оконная сборка с системными библиотеками графики |
| Виртуальная машина без аппаратной графики | Поведение при отсутствии поддержки графики |

## 4. Требования к системе

### 4.1 Требования к структуре системы

#### 4.1.1 Состав и ответственность компонентов

| Компонент | Ответственность | Ограничения |
|---|---|---|
| Ядро обработки | Инвентаризация, загрузка, сборка, проверка, отчёт | Не зависит от интерфейса и от ввода пользователя |
| Разбор адреса | Приведение пользовательского ввода к домену | Чистая функция: без сети и без файлов |
| Слой сети | Соединения, повторы, паузы, ограничение темпа | Единая точка сетевого доступа для ядра |
| Слой кодировок | Выбор кодировки, декодирование, нормализация в UTF-8 | Не зависит от сети и файловой системы |
| Слой путей | Адрес в путь файла, ограничения файловых систем | Не обращается к состоянию прогона |
| Интерфейс | Окно, прогресс, журнал, справка, настройки | Не выполняет сетевых операций в потоке интерфейса |
| Командная строка | Разбор параметров, вывод, коды возврата | Не дублирует логику ядра |
| Локализация | Строки интерфейса и сообщения ядра на двух языках | Единый источник строк |

#### 4.1.2 Конвейер обработки

Пять последовательных стадий: инвентаризация → загрузка → сборка → проверка → отчёт.

- Каждая стадия идемпотентна по своему результату: сырые файлы переиспользуются,
  собранная копия пересобирается полностью.
- Все стадии, кроме проверки и отчёта, прерываются по команде пользователя.
- Обработка выполняется вне потока интерфейса; интерфейс получает снимки состояния и
  не блокируется на время сетевых операций.

#### 4.1.3 Выходной каталог

```
<папка>\
  site\                  — готовая копия, её открывают локальным сервером
  mirror\                — исходные файлы из архива
  data\inventory.jsonl   — инвентарь: по строке на адрес
  data\content-types.tsv — тип содержимого по каждому полученному файлу
  report.html            — отчёт о полноте
```

| Объект | Формат | Назначение |
|---|---|---|
| `inventory.jsonl` | JSON Lines, UTF-8, поля: адрес, метка снимка, исходный адрес, тип содержимого, путь, класс файла | Воспроизводимость и повторный запрос конкретного снимка |
| `content-types.tsv` | Пары «путь в копии — тип содержимого» | Подсказка кодировки при сборке |
| `report.html` | Самодостаточный HTML, UTF-8 | Отчёт о покрытии, открывается без сервера |
| `*.part` | Байты в процессе записи | Атомарность; не считается готовым файлом |

#### 4.1.4 Состояние и параметры

- Настройки пользователя сохраняются между запусками: последний адрес, папка результата,
  язык интерфейса.
- Настройки хранятся в файле профиля пользователя, читаются устойчиво к повреждению и
  к наличию служебных символов в начале файла; при повреждении берутся значения по умолчанию.
- Технические параметры прогона задаются параметрами командной строки и переменными
  окружения: адрес и папка для автоматического старта, язык, режим краткого журнала,
  файл диагностики ввода.

### 4.2 Требования к функциям

#### 4.2.1 Ввод и нормализация адреса

| ID | Требование | Критерий приёмки |
|---|---|---|
| ФТ-01 | Принимать адрес в любом виде: домен без схемы, полный адрес, со схемой в любом регистре, с путём, портом, якорем и завершающей точкой | Из каждой формы получается один и тот же домен |
| ФТ-02 | Удалять невидимый мусор вставки: нормализация Unicode, символы нулевой ширины, метка порядка байтов, мягкий перенос, неразрывный пробел, типографские кавычки и тире | Адрес, скопированный из мессенджера или документа, распознаётся |
| ФТ-03 | Извлекать настоящий адрес из ссылки-обёртки: адрес снимка архива с указанием времени и без него, ссылки поисковых систем с параметрами запроса | Возвращается исходный домен, а не домен архива или поисковика |
| ФТ-04 | Различать две причины кириллицы: текст, набранный в русской раскладке, и настоящий кириллический домен | `зкщлгзщдюкг` даёт `prokupol.ru`; `прокупол.рф` даёт домен в punycode |
| ФТ-05 | Переводить кириллический домен в punycode с проверкой формы | Метка не длиннее 63 символов, домен не длиннее 253, уже закодированный домен не кодируется повторно |
| ФТ-06 | Отклонять ввод, из которого домен не получается: пустая строка, слово без точки, только схема, связный текст | Поле не изменяется, пользователь видит предупреждение |
| ФТ-07 | Чистить вставку: управляющие символы, переводы строк, разметку ссылки вида «текст в скобках», кавычки, угловые скобки, повторные пробелы; из нескольких адресов брать первый | Вставка из браузера, письма, документа и разметки даёт домен |
| ФТ-08 | Показывать разбор под полем: итоговый домен, причину преобразования и путь первого файла копии | Подсказка начинается со стрелки; при непригодном вводе — предупреждение |
| ФТ-09 | Обновлять разбор по паузе набора, не переписывая поле | Через 0,4 секунды после последней клавиши подсказка актуальна |
| ФТ-10 | Нормализовать поле при уходе фокуса, по клавише Enter и по отдельной кнопке; Enter в поле запускает прогон; Esc снимает фокус | После клика вне поля в нём остаётся домен |
| ФТ-11 | Передавать фокус полю адреса при открытии окна | Вставка из буфера работает сразу, без клика мышью |
| ФТ-12 | Поддерживать способы вставки: основное сочетание клавиш, сочетание с Shift, Shift+Insert, средняя кнопка мыши в графических средах, где это принято | Поведение совпадает с таблицей способов вставки в документации |
| ФТ-13 | Читать и записывать буфер обмена собственными средствами системы на Windows | Вставка из другого приложения работает; копирование доходит до буфера |
| ФТ-14 | Сохранять последние значения между запусками: адрес, папка результата, язык | После перезапуска поля заполнены прежними значениями |

#### 4.2.2 Инвентаризация архива

| ID | Требование | Критерий приёмки |
|---|---|---|
| ФТ-15 | Определять объём архива пробным запросом до загрузки | Пользователь видит число страниц индекса в журнале |
| ФТ-16 | Распознавать все известные форматы ответа о числе страниц: объект с полем, пары «ключ — значение» и одиночное число | Любой формат даёт верное число страниц |
| ФТ-17 | Выполнять быстрый запрос списка адресов независимо от числа страниц, до трёх попыток | Инвентарь на крупном домене содержит тысячи адресов, а не один |
| ФТ-18 | Обходить индекс постранично для крупных доменов: по 20 000 записей, не более 200 страниц | Крупный домен собирается полностью в пределах лимита |

### 8.2 Что считается дефектом

- Текст в копии не читается или содержит признаки неверной кодировки.
- Ссылка в копии ведёт на абсолютный адрес исходного домена.
- Файл, присутствующий в архиве, отсутствует в копии без записи в ошибках.
- Приложение завершается аварийно вместо сообщения при отказе архива.
- Числа отчёта расходятся с содержимым копии.
- Файл, который можно принять за готовый, оказывается неполным.
- Имя файла в релизе не совпадает с обещанным в документации.
- Исполняемый файл не запускается на чистой системе целевой платформы.

### 8.3 Порядок устранения

Дефект фиксируется в списке изменений с указанием версии исправления. Дефекты классов
«неверная кодировка», «абсолютные ссылки в копии» и «неполный файл под итоговым именем»
считаются блокирующими для выпуска.

## 9. Порядок ведения документа

Настоящее техническое задание — единственный документ требований к продукту.
Отдельных заданий по версиям, платформам или модулям не ведётся: новое требование
добавляется сюда, устаревшее заменяется или удаляется, дублирование не допускается.

| Правило | Содержание |
|---|---|
| Порядок изменения | Требование формулируется и получает критерий приёмки, затем реализуется, затем проверяется по этому критерию |
| Нумерация | Идентификаторы требований не переиспользуются: удалённое требование оставляет пропуск в нумерации |
| Полнота | Новое поведение продукта без требования в этом документе не считается согласованным |
| Версия документа | Повышается при изменении состава требований; текущая версия указана в шапке |
| Согласованность | Приложения (словарь, ограничения, контрольные значения) обновляются вместе с требованиями |
| Сопровождение доработки | Любая доработка сопровождается правкой этого документа в том же изменении: требование добавлено или заменено, критерий приёмки сформулирован, версия документа повышена |
| Проверка при приёмке | Изменение без соответствующей правки требований не принимается, даже если код работает |

Что относится к доработкам, а что — нет:

| Относится к доработкам | Не относится |
|---|---|
| Новая функция или возможность | Внутренняя перестройка кода без изменения поведения |
| Изменение поведения, интерфейса, состава отчёта, формата данных | Правка опечаток и оформления документов |
| Изменение требований к поставке, совместимости, безопасности, производительности | Обновление зависимостей без изменения поведения |
| Исправление дефекта, из-за которого требование не выполнялось | Ускорение сборки и другие работы над процессом разработки |

| Версия документа | Изменение |
|---|---|
| 1.0 | Первая редакция: цели, требования по группам, приёмка |
| 2.0 | Требования изложены нормативно, критерии приёмки вынесены в каждую группу, добавлены контрольные значения и перечень контрольных проверок |
| 2.1 | Закреплено сопровождение: каждая доработка сопровождается правкой требований в том же изменении |
