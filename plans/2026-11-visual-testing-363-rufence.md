# Расширенное визуальное тестирование Windows и Linux GUI (rufence.ru)

Документ задачи, версия 1.0, 14–15.11.2026. Предмет: визуальная часть оконной сборки —
компоновка, индикаторы, отображение процесса и ожидания — на живом скачивании копии
rufence.ru, в Windows- и Linux-сборках. Снимки, замеры и правки перечислены ниже.

## 1. Что было поставлено

> Используя навыки дизайна проведи расширенное тестирование визуальной части Windows GUI
> Linux GUI сборок на скачивании копии сайта rufence.ru. Смотри в живую. Детально
> просматривай скриншоты. Внимательно осматривай каждый элемент на окне программы.
> Внимательно осматривай компоновку элементов в окне программы. Смотри на поведение
> программы изменение индикаторов индикацию процесса (как программа отображает изменения
> как программа отображает процесс, как программа отображает простой или ожидание данных)
> Для тестирования можешь использовать мой компьютер и мои виртуальные машины и мой WSL
> контейнер.

Отсюда пять требований: (1) обе сборки, (2) живой прогон rufence.ru, (3) покадровый
разбор каждого элемента, (4) разбор компоновки, (5) разбор поведения индикаторов —
включая простой и ожидание данных.

## 2. Как тестировалось

**Сборки.** Windows — `cargo build --release` (GUI, 9 265 152 Б, коммит `284c539`).
Linux — та же ревизия, собранная в WSL Kali (`cargo build --release --features gui`,
3 м 04 с), запуск под WSLg: `DISPLAY=:0`, `WAYLAND_DISPLAY=wayland-0`, программный
рендеринг (в логе `MESA: error: ZINK: failed to choose pdev` — это ожидаемо без GPU).

**Сайт.** rufence.ru: по CDX 5 470 адресов (`collapse=urlkey`, только `statuscode:200`),
из них 3 949 HTML-страниц, 1 028 изображений, 412 CSS/JS/XML. Прогоны — строго по одному:
архив блокирует параллельные обращения.

**Съёмка.** Клиентская область окна, кадр каждые 200–2000 мс (`scratch\capture-loop.ps1`
для обычного окна, `scratch\capture-title.ps1` для окна WSLg — там процесс `msrdc`).
Всего 1 500+ кадров на Windows и 500+ на Linux; кадры с одинаковым содержимым
отбрасывались по md5.

**Замеры.** Кроме просмотра глазами: `scratch\ui-probe.py` (отрезки цвета по строке и
столбцу, контраст текста по пикселям), `scratch\ui-compare.py` (габариты текстовых
блоков для сверки платформ), `scratch\ui-analyze.py` (палитра и границы блоков).
Контраст считался по формуле WCAG (относительная яркость), а не на глаз.

**Навыки дизайна.** `desktop-ui-feedback-messaging` (выбор носителя сообщения, состояния
загрузки, пустые состояния), плюс общая сетка `desktop-ui-*`: контраст, ритм отступов,
плотность, размеры целей.

**Окна, которые проверялись.** 900×660 (размер по умолчанию), 760×560 (минимум по
`with_min_inner_size`), 1 180×860 (высокое окно). Размер задавался через файл настроек
(`window_w`/`window_h` — ключи плоские, вложенный `window` не читается) и через
`SetWindowPos`; второй способ под WSLg ненадёжен (поверхность меняется, приложение о
новом размере не узнаёт).

### 3.3 Совпадение платформ

Габариты текста совпадают до пикселя (шрифты встроены в egui): заголовок 338×20,
подзаголовок 574×10, подпись поля 67×7, строка-подсказка 147×9, надпись кнопки 39×7 —
одинаково в Windows и Linux. Различий рендеринга шрифта между сборками нет; отличие
только в путях и в текстах системных ошибок.

## 5. Правки в коде (файлы и суть)

- `src/app.rs`:
  - карточка прогресса: `auto_shrink([false, true])`, убраны лишние отступы, разделитель
    рисуется одной строкой высотой 1 px, блок типов адаптивный (полосы ↔ строка с числами),
    блоки включаются по `available_height()` с порогами 104 / 50 / 16 / 24 px;
  - `human_eta` — часы/минуты/секунды по языку окна;
  - `push_log` — дедупликация подряд идущих записей с счётчиком «×N»;
  - `Level` получил `PartialEq`, добавлены `OK_TEXT`/`WARN_TEXT` для мелкого текста.
- `src/i18n.rs`: единицы времени (`ч/мин/с`, `h/min/s`).
- `src/core.rs`: `explain_net` — человеческая причина сетевой ошибки с кодом в скобках
  (10061 / 10054 / 10060 / 10051 / DNS, для Linux — те же коды errno), используется во всех
  пяти местах журнала, включая добор; тест `net_errors_get_plain_reason`;
  сообщения добора по ссылкам переписаны по-человечески (`rescue:…` больше нет).
- `src/app.rs` (продолжение): метка и янтарная точка паузы; `stage_chip` получил состояние 3.

## 7. Чего этот документ не утверждает

- Linux проверен под WSLg с программным рендерингом (llvmpipe/ZINK не выбирается):
  цвет и геометрия совпадают с Windows, но частота кадров там ниже, и «плавность»
  анимаций этой проверкой не подтверждена.
- HiDPI не проверялся: масштаб 100 % (2560×1440). При 125–200 % размеры и отступы могут
  потребовать пересмотра порогов 104/50/16/24 px.
- Сборки 3.6.3 в релизе — без этих правок: они сделаны после выпуска и в релиз не входят;
  для них нужен отдельный выпуск (3.6.4).
- Ошибки архива (503, 429, `connection refused`) — состояние внешнего сервиса, а не
  программы; в тестах они полезны как источник состояний ожидания.
- Оценки «красиво/некрасиво» здесь не выносятся: перечислены измеримые вещи (габариты,
  контраст, что именно видно в каждом состоянии).
