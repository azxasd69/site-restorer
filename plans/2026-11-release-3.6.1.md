# План релиза 3.6.1 «Возможности процессора и разбор без копий»

Дата: 12.11.2026. Основание: решения владельца по трём вопросам разбора
(`plans/2026-11-isa-analysis.md` §8), План §4.6 и §5.6, ТЗ 2.19.

## 0. Решения владельца и что из них следует

| Вопрос | Ответ | Что сделано/следует |
|---|---|---|
| Своя проверка целостности копии (локальный SHA-256, SHA-NI) | **нет** | ускорение SHA не вводится; отпечаток по-прежнему берётся из CDX (`fl=…,digest`); в плане нет работ по `sha2` |
| Отдельная быстрая сборка `x86-64-v3` | **нет** | один бинарник на весь парк x86-64; имена ассетов релиза стабильны; все ускорения — только runtime dispatch |
| Прекращение 32-битных сборок (Д-57) | **сразу** | выполнено 12.11.2026: матрица, нормы ПР-6, РЛ-12, сайт (RU/EN), README, BUILD, PUBLISH, RELEASE, ARCHITECTURE, llms.txt, проверка ссылок |

Следствие для архитектуры: раз отдельной быстрой сборки нет и AVX-512 не
вводится, единственный законный путь ускорения — библиотеки с собственной
диспетчеризацией (`memchr`, `regex`, `encoding_rs`, `flate2`) плюс, при
необходимости, собственные `#[target_feature]`-функции со скалярным двойником.

## 2. Шаг 1 — разбор индекса по срезам (Д-64)

**Замер, на котором основан шаг:** страница ответа CDX на 20 000 строк
(2,01 МБ) разбирается текущим кодом за 47,9 мс, байтовым разбором по срезам —
за 5,5 мс (**8,8×**). Причина: `Vec<char>` — 4 байта на символ, плюс
`String` на каждое из шести полей каждой строки (120 000 аллокаций на
страницу), плюс копия тела из `String::from_utf8_lossy`.

**Что менять.** `src/core.rs`, функция `parse_rows` (около строки 4467) и пять
мест вызова (1122, 1970, 2134, 2262, 2649).

```rust
/// Строка ответа CDX: границы полей в исходном теле, без копий.
pub(crate) struct Row {
    url: (u32, u32),
    mime: (u32, u32),
    status: (u32, u32),
    length: (u32, u32),
    digest: (u32, u32),
    timestamp: (u32, u32),
}

impl Row {
    pub(crate) fn url<'a>(&self, body: &'a [u8]) -> &'a str {
        field(body, self.url)
    }
    // остальные поля — так же
}

fn field<'a>(body: &'a [u8], r: (u32, u32)) -> &'a str {
    std::str::from_utf8(&body[r.0 as usize..r.1 as usize]).unwrap_or("")
}

pub(crate) fn parse_rows(body: &[u8]) -> Vec<Row> {
    // один проход: memchr по '[' находит начало строки данных,
    // memchr2 по '"' и '\\' — конец поля; экранирование обрабатывается
    // отдельной ветвью (редкий случай), остальные поля остаются срезами
}
```

**Требования к поведению:**

1. Совпадение результатов с прежним разбором на реальных ответах: сравнить
   `url/mime/status/length/digest/timestamp` по всем строкам трёх сохранённых
   ответов (можно снять `--dump-index` при прогоне), расхождений быть не должно.
2. Экранирование (`\"` внутри адреса) и границы (`[`, `]`, обрыв тела на
   середине строки) — тестами; существующий тест `parse_rows_handles_escapes`
   переписать на новый интерфейс, а не удалять.
3. Пиковая память под страницу — не выше двух объёмов тела (сейчас примерно
   шесть: тело + `String` из `lossy` + `Vec<char>` + строки полей).

**Критерий приёмки:** замер в `benches/` показывает не менее 5× ускорения
(фактически ожидается 8,8×), память укладывается, тесты зелёные.

## 3. Шаг 2 — `isa` и выключатель (Д-65)

**Новый модуль `src/isa.rs`.** Возможности определяются один раз, кэшируются и
попадают в отчёт: без такой строки разбор обращения «у меня вылетело»
невозможен.

```rust
//! Возможности процессора: определяются один раз, кэшируются, попадают в отчёт.

use std::sync::OnceLock;

#[derive(Debug, Clone, Copy)]
pub struct Isa {
    pub avx2: bool,
    pub sha_ni: bool,
    pub popcnt: bool,
    /// Ускорения выключены вручную (SR_NO_SIMD=1).
    pub forced_scalar: bool,
}

pub fn caps() -> &'static Isa {
    static CAPS: OnceLock<Isa> = OnceLock::new();
    CAPS.get_or_init(detect)
}

fn detect() -> Isa {
    let forced = std::env::var_os("SR_NO_SIMD").is_some_and(|v| v != "0");
    #[cfg(any(target_arch = "x86_64", target_arch = "x86"))]
    {
        use std::arch::is_x86_feature_detected as has;
        Isa {
            avx2: !forced && has!("avx2"),
            sha_ni: !forced && has!("sha"),
            popcnt: !forced && has!("popcnt"),
            forced_scalar: forced,
        }
    }
    #[cfg(not(any(target_arch = "x86_64", target_arch = "x86")))]
    {
        Isa { avx2: false, sha_ni: false, popcnt: false, forced_scalar: forced }
    }
}

pub fn describe() -> String { /* «CPU: avx2=true sha-ni=true popcnt=true» */ }
```

**Куда выводить:** первая строка отчёта (`report.html`, секция «Здоровье» или
шапка) и `--version --verbose`. В обычном `--version` — не выводить, чтобы не
ломать разбор версии скриптами.

**Форма диспетчера** (проверено компилятором 12.11.2026: собирается):
объявление функции с `#[target_feature]` может быть безопасным, но вызов
требует `unsafe`, если у вызывающего нет тех же возможностей.

```rust
#[target_feature(enable = "avx2")]
fn scan_avx2(body: &[u8]) -> usize { /* тело — безопасный код */ }

fn scan_scalar(body: &[u8]) -> usize { /* то же безопасно, но без AVX2 */ }

pub fn scan(body: &[u8]) -> usize {
    if caps().avx2 {
        // SAFETY: наличие AVX2 проверено во время работы.
        unsafe { scan_avx2(body) }
    } else {
        scan_scalar(body)
    }
}
```

**Запрещено обзором кода:** `cfg!(target_feature = "avx2")` как проверка
возможностей (это проверка при компиляции, при базовой ISA всегда ложна);
`unsafe fn` для версий с возможностями (расширяет недоверенную зону).

**Критерий приёмки:** строка возможностей видна в отчёте и в
`--version --verbose`; при `SR_NO_SIMD=1` она содержит пометку о ручном
выключении; полный набор тестов с выключателем проходит.

## 4. Шаг 3 — распаковка на чистом Rust (Д-66)

`flate2` приходит через `ureq` с умолчанием `miniz_oxide` (скаляр). Переключить
бэкенд и не тащить C:

```toml
flate2 = { version = "1", default-features = false, features = ["zlib-rs"] }
```

Проверки: сборка без C-компилятора (в конвейере это уже так), musl-статика
собирается, распакованные файлы совпадают по SHA-256 с прежними на трёх сайтах
разного размера. `zlib-ng` не берём: требует `cmake` и ломает статическую musl.

**Критерий приёмки:** три прогона дают побайтово те же файлы; замер
распаковки в `benches/` не хуже прежнего (ожидается 1,5–2,5× быстрее).

## 5. Шаг 4 — меньше копий в разборе адресов (Д-67)

- `sanitize::pct_decode` (`src/sanitize.rs:119`) всегда делает `Vec` и
  `from_utf8_lossy`. Быстрый выход: если `%` в строке нет — вернуть
  `Cow::Borrowed`. Таких адресов большинство.
- `String::from_utf8_lossy` в горячих местах (тело ответа индекса уже
  закрывается шагом 1) → быстрый валидатор UTF-8 (`simdutf8`) с падением на
  `lossy` только при ошибке.

**Критерий приёмки:** тесты разбора адресов проходят; замер на наборе из 10 000
адресов не медленнее прежнего; на адресах без `%` аллокаций нет (проверить
счётчиком аллокаций в бенче).

## 6. Шаг 5 — замеры и гейты в конвейере (Д-68)

**`benches/`** (criterion, dev-dependency): `parse_rows`, `rewrite_html`
(переписывание разметки на сохранённой странице), `pct_decode`, `gunzip`.
Замеры не входят в релизные артефакты.

**Конвейер, две задачи:**

```yaml
  # Базовая ISA и выключенные ускорения: то, что обещано самым старым машинам.
  isa-floor:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: cargo test --no-default-features
        env:
          RUSTFLAGS: "-C target-cpu=x86-64"
          SR_NO_SIMD: "1"

  # Числа для сравнения: не блокирует релиз, падение не мешает выпуску.
  isa-bench:
    runs-on: ubuntu-latest
    continue-on-error: true
    steps:
      - uses: actions/checkout@v4
      - run: cargo bench --no-default-features -- --output-format bencher
        env:
          RUSTFLAGS: "-C target-cpu=x86-64-v3"
```

**Критерий приёмки:** `isa-floor` зелёный; в CHANGELOG записаны цифры до/после
по разбору индекса и распаковке.

## 7. Шаг 6 — единый источник флагов (Д-69)

Сейчас флаги заданы дважды, и `RUSTFLAGS` из матрицы **полностью перекрывает**
`.cargo/config.toml`: правка в файле в конвейере не действует, и это ничем не
проверяется.

1. Перенести в `.cargo/config.toml` всё, включая линковщик musl:

```toml
[target.x86_64-unknown-linux-musl]
linker = "musl-gcc"
rustflags = ["-C", "target-cpu=x86-64"]
```

2. Убрать `RUSTFLAGS` из релизных ячеек матрицы (оставить только в `isa-bench`
   и в задачах, где нужна вариантная сборка).
3. Добавить `scripts/check-flags.py`: падает, если в репозитории или конвейере
   встречается `target-cpu=native`, `x86-64-v2/v3/v4`, глобальные
   `+avx/+avx2/+fma/+sse4.*`, либо если действующие флаги ячейки не совпадают
   с файлом.

**Критерий приёмки:** релизная сборка использует только файл; проверка ловит
подложенные нарушения (проверить тремя подложенными строками).

## 9. Риски и как снимаем

| Риск | Проявление | Мера |
|---|---|---|
| Ошибка в разборе индекса | копия собирается неполной, падения нет — самый опасный класс | сравнение с прежним разбором на реальных ответах, тесты экранирования и границ, отчёт о полноте (ФТ-155) как контроль |
| Смена бэкенда распаковки | файл отличается одним байтом | сверка SHA-256 с прежними прогонами |
| `SR_NO_SIMD` не покрывает путь | у пользователя старый CPU и вылет | прогон всего набора с выключателем в конвейере (`isa-floor`) |
| Расхождение файла и конвейера | релиз собран не теми флагами | `check-flags.py` в гейтах |
| Замеры на раннере шумят | ложные выводы о регрессе | `isa-bench` не блокирует; сравнение по медиане из пяти прогонов |

## 10. Что в этом релизе не делаем

- свою проверку целостности и SHA-NI — **отклонено владельцем**;
- сборку `x86-64-v3` — **отклонено владельцем**;
- AVX-512 — запрещено политикой (частота на гибридных ядрах, выигрыш не измерен);
- собственный SIMD-код — профиль не показывает узкого места, `memchr` и `regex`
  уже диспетчеризуют внутри;
- macOS, wgpu, Control Flow Guard — это 3.7.0 (Д-59, Д-60, вторая часть Д-63).
