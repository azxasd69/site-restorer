## 4. Проблемы, которые план обязан закрыть

1. **Адрес `/admin/`** — не «только по ссылке». Нужен неугадываемый сегмент пути.
2. **Нет входа через GitHub** — требование владельца не выполнено.
3. **Данные — снимок**: свежесть определяется запуском сборщика, расписания нет.
4. **Вебмастер пуст** — без действия владельца раздел останется с одной диагностикой.
5. **Снимок не закоммичен** — при падении машины работа пропадёт.
6. **Пароль в файле** — при утечке файла данные открыты; есть режим `--rotate`.

## 5. Три направления доступа

### A. Пароль + секретный путь (статическая страница, как сейчас, но доделать)

- Как: снимок шифруется AES-256-GCM; папка переименовывается в `/admin-<случайные 12 символов>/`;
  ссылки с сайта нет, `noindex`, `robots.txt` путь не выдаёт.
- Плюсы: ноль инфраструктуры, данные защищены криптографией, работает на GitHub Pages, ничего не ломается.
- Минусы: нет GitHub-входа; обновление — запуском скрипта (или задачи планировщика).
- Когда применимо: «нужна сводка, которой я доверяю, и не нужно ставить сервер».

### B. A + вход через GitHub device flow (без сервера)

- Как: страница просит открыть `github.com/login/device` и ввести 8-символьный код; клиент GitHub-приложения
  публичный (секрет не нужен), после подтверждения страница проверяет логин в списке разрешённых.
- Плюсы: формально «вход через GitHub», без сервера и без секретов в коде.
- Минусы: **это замок на двери без стены** — защиту обходит любой, кто откроет консоль;
  реальная защита данных всё равно остаётся у пароля. Токен живёт в браузере, UX с копированием кода.
- Когда применимо: требование «или GitHub» обязательно, а сервер поднимать не хочется.

### C. Сервер на VPS testib.ru: пароль + GitHub OAuth, живые данные

- Как: небольшой сервис (Node/Python) на testib.ru: страница логина (пароль + GitHub OAuth с секретом),
  сессия в httpOnly-cookie, данные тянутся из API Метрики и GitHub на сервере, токены не покидают сервер.
  Админка остаётся на lastcopy.ru и обращается к `api.testib.ru` по CORS с проверкой Origin.
- Плюсы: настоящая авторизация (секрет OAuth, серверные сессии), свежие данные без пересборки,
  ссылка `lastcopy.ru/admin-<slug>/` без пароля в адресе, можно добавить «обновить сейчас».
- Минусы: новый сервис на 1 vCPU/865 МБ (там уже 330 МБ занято), хранение токенов Метрики/Вебмастера на VPS,
  DNS/сертификат для поддомена, обслуживание и обновления; снимок больше не нужен, но появится зависимость от сервера.
- Когда применимо: данные нужны «прямо сейчас», а не вчерашние; и владелец готов держать сервис.

**Рекомендация:** A как база (сегодня, без риска) + при желании C позже, если станет тесно от снимков.
B — только если «вход через GitHub» нужен как формальное требование.

## 9. Критерии приёмки

1. Адрес неугадываемый, `noindex` на странице, ссылок с сайта и из sitemap нет.
2. Без пароля в браузер не попадает ни одного значения статистики (проверка: в исходниках и в сети — только шифротекст).
3. Неверный пароль: понятное сообщение, без раскрытия данных, с задержкой на повтор.
4. Все секции §6 заполнены реальными числами; где данных нет — объяснение словами, а не «—».
5. Экспорт JSON отдаёт тот же снимок, что видит страница.
6. Живая проверка: вход с телефона и с компьютера, вёрстка не ломается на 390 px.
7. `style.css`/ассеты админки версионированы, повторный визит не показывает старую версию.
