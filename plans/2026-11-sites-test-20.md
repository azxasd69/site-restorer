# Испытания 20 сайтов на Windows 10 (x86, 8 ядер)

**Что это.** Расширенные испытания версии 3.4.0: двадцать сайтов на разных системах управления,
разного объёма, на отдельной виртуальной машине. Цель — проверить сборку копии и проверку
ссылок на разнородном материале, а не только на демонстрационных копиях.

**Дата.** 11.11.2026. **Стенд.** Hyper-V, гость `Win10-x86` (Windows 10 Pro 19045, 32-разрядная,
8 виртуальных процессоров, диск динамический 50 ГБ, свободно 29 ГБ, экран 1024×768).
Сборка продукта — `i686-pc-windows-msvc`, статический CRT, 5,95 МБ. Обмен файлами и командами —
`tools\vm\g.py` (SSH), без интерактивного рабочего стола.

**Как считали.** Каждый сайт — отдельный прогон `--cli --site <адрес> --out C:\sr\out\<сайт>
--limit N`, лимит зависел от размера сайта. Время — от запуска процесса до строки `RESULT`,
включая обращение к индексу архива, загрузку и сборку.

## Что показали испытания

**Сборка работает на всех типах CMS.** WordPress, Bitrix, Joomla, MODX, Tilda, Drupal, Umbraco,
Django, Laravel, Hugo, Jekyll, MediaWiki и статические сайты (nginx, sqlite, gnu) собраны одной
и той же сборкой без правок. Ошибок сборки, падений и «неизвестных символов» в журнале нет.

**Время определяется сетью, а не сборкой.** На копии из 599 файлов (ru.wikipedia.org) прогон
занял 154 с, из них сборка — доли секунды. На копии 300 файлов — 98…353 с в зависимости от
скорости ответа архива. Это ожидаемо после ускорения 3.4.0: узкое место — инвентаризация
и загрузка из архива, а не обработка файлов.

**Высокая доля битых ссылок — свойство архива, а не дефект сборки.** У ru.wikipedia.org все
108 848 ссылок «битые», потому что это ссылки на другие статьи Википедии, которых в копию не
брали (лимит 600 адресов). То же у 1c-bitrix.ru (30 024 из 31 621) и gohugo.io (16 247 из 23 396):
внутренние ссылки уходят за пределы выбранной части сайта. Число совпадает с проверкой 3.3.1
на тех же копиях, методика подсчёта не изменилась.

**sqlite.org — 297 файлов при 1 странице.** Сайт отдаёт документацию как `.txt`/`.html`-фрагменты
без обычной разметки; файлы копируются, но страницами не считаются. Это поведение ФТ-118:
под видом страницы не страница не учитывается как страница, но файл остаётся на месте.

**Шесть сайтов дали одну страницу — ограничение архива, а не продукта.** Для wordpress.org,
react.dev, vuejs.org, gnu.org и opencart.com индекс `web.archive.org` в момент прогона отвечал
кодом 503 или по таймауту (проверено отдельными запросами), после чего продукт получал только
главную страницу. Для market.1c-bitrix.ru в архиве почти нет снимков (одна запись в CDX-индексе).
Повторная проверка шести сайтов по одному, с паузой 60 с и тремя потоками, дала тот же итог:
ограничение держалось. **Исправлено по итогам:** если индекс отказал, а в списке оказалась одна
страница, в журнал идёт строка «архив отдал только главную страницу — вероятен отказ индекса
(503 или предел частоты), повторите прогон позже». Раньше такой прогон выглядел успешным.

**Интерфейс проверить на стенде не удалось.** В гостевой системе нет интерактивного сеанса
(экран 1024×768 пуст, окно программы не открывается — сообщение об отсутствии OpenGL 2.0),
на рабочей машине окно открывается, но содержимое не отрисовывается (та же картина у релизной
сборки 3.3.1, то есть это свойство среды, а не регресс 3.4.0). Замечания по интерфейсу даны
по снимкам версии 3.3.0 из `docs/screenshots`; правки, которые из них следуют, внесены
(подписи карточки прогресса по этапам, окраска ошибок в журнале).

## Замечания по интерфейсу, внесённые в 3.4.0

| Замечание | Что сделано |
|---|---|
| На этапе сборки карточка называлась «Скачано» и показывала скорость сети — непонятно, идёт ли работа | «Обработано N / M» и файлов в секунду; «Скачано» и «Скорость» только на загрузке |
| Ошибки движка в журнале выглядели как обычные строки | Строки с «не удалось», «ошибка», «cannot», «failed» окрашиваются как предупреждения |
| Предупреждение об отказе индекса отсутствовало | Явная строка в журнале при одной странице в списке после отказа |

Остальные замечания по снимкам (высота журнала, плотность карточек при ширине 760 px,
единообразие подписей этапов) перенесены в план: релиз 3.5, пункт Д-21 (настройка потоков
и темпа в окне) и доработки оформления.

## Как повторить

```
# сборка под 32-разрядную гостевую систему
$env:RUSTFLAGS='-C target-feature=+crt-static'
cargo build --release --target i686-pc-windows-msvc

# прогон списка сайтов (нужен доступ к гостю через tools\vm\g.py)
python scratch\vm-sites.py
python scratch\vm-sites-summary.py scratch\vm-sites-result.json
```
