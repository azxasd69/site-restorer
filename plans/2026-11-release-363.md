## 2. Архитектурное ревью

Проводилось по коду и по поведению, до код-ревью. Найдено и исправлено:

1. **Политика путей была рассыпана.** `long_path` существовал, но применялся только к удалению
   дерева; остальные операции шли без префикса. Итог: на системе без `LongPathsEnabled` поддеревья
   молча выпадали. Исправлено — все операции через `long_path`, каталог вывода приводится к полной
   форме один раз (`canonical_dir`).
2. **Префикс `\\?\` отключает разбор путей системой.** Это не только `..`, но и подстановка
   коротких имён 8.3: путь `C:\Users\7636~1\AppData\Local\Temp\...` с префиксом не находится
   («Системе не удаётся найти указанный путь»). Обнаружено тестами: 9 тестов сборки копии падали.
   Решение: каталог вывода один раз приводится к полной форме, дальше префикс безопасен.
3. **Счётчик непрочитанных каталогов складывался при каждом обходе**, а одно дерево обходится до
   трёх раз за прогон — число в отчёте завышалось бы. Сделано «один раз на дерево».
4. **Схема доступа к архиву «сдавалась» из-за медленного ответа** (подробно в §4): архитектурно это
   смешение «адрес недоступен» и «адрес отвечает медленно». Разделено.
5. **Ошибка чтения каталога терялась** в `else { continue }` — числа отчёта занижались без следа.
   Теперь `walk_files` возвращает `(файлы, непрочитанные)`, значение видно в отчёте и в `RESULT`.
6. Осталось архитектурным долгом (в 3.7.0): политика путей живёт в `core.rs`, хотя рядом есть
   `paths.rs`; расхождение «процент этапа» и плитки «Обработано»; неактивные кнопки визуально
   почти не отличаются от активных.

число мест `{}` в строке `RESULT`, платформенные коды ошибок, синтаксис CI-матрицы.

Найдено четыре замечания, все исправлены:

## 4. Живые прогоны (реальные сайты, строго по одному)

Архив блокирует параллельные обращения, поэтому все прогоны — последовательные, пауза между ними.

| Прогон | Что проверялось | Результат |
|---|---|---|
| `neverssl.com --limit 8` (3.6.2, до правок) | базовая линия | 8/8, но `"archive":"http"` — программа уже «сдалась» на http |
| `no-such-domain-zz9.example` (3.6.2) | домен, которого нет в архиве | ~2 минуты на 4 %, затем `archive unavailable`; окно «висело» |
| `neverssl.com` (GUI, полностью, сборка до Д-108) | визуальные стадии на реальной работе | 1844 адреса, 1686 файлов скачано, 1033 страницы, отчёт собран; в журнале «запись: gzip decompression failed: invalid gzip header», счётчик «Битые / ошибки 4/104» |
| `neverssl.com` (GUI, полностью, сборка после Д-110…Д-112) | те же стадии после правок интерфейса | статус «Готово, с замечаниями», 1844/1844, «3 / 155», журнал прокручен к концу, строка итога с путём к отчёту видна целиком |
| `neverssl.com --limit 8 --workers 2` (3.6.3) | схема архива после правки | 8/8, `"archive":"https"`, `"unreadable":0`, 10 запросов |
| `neverssl.com --limit 3 --out <путь 131 символ>` (3.6.3) | длинный каталог вывода | 3/3, отчёт на месте |
| `neverssl.com --limit 2 --out <путь 276 символов>` (3.6.3) | путь длиннее 260 | 2/2, копия и отчёт собраны — предел системы не мешает |
| `no-such-domain-zz9.example` (3.6.3) | пустой индекс | код 1, «в архиве нет страниц», без постраничного обхода |
| Опубликованные ассеты (`SiteRestorer-windows-x64-cli.exe` из релиза) | артефакт релиза, а не локальная сборка | 3/3, `RESULT` с `"archive":"https"` |

Что дали прогоны (три дефекта, исправлены и вошли в релиз):

1. **Схема архива.** https отдавал CDX за 15–25 с, срабатывал таймаут чтения, программа уходила на
   http (порт 80 недоступен) и падала на инвентаризации. Теперь схема меняется только при отказе
   соединения; если и запасная схема не отвечает три раза — возврат на https (Д-97 уточнён).
2. **Сжатие файлов.** Архив иногда помечает тело `Content-Encoding: gzip`, хотя внутри не gzip —
   файл терялся. Файлы копии теперь запрашиваются без сжатия передачи (Д-108): в зеркало попадают
   байты архива, а не результат распаковки. Индекс (JSON) остаётся со сжатием.
3. **Пустой индекс.** Домен, которого нет в архиве, висел на 4 % около двух минут: пустой быстрый
   ответ запускал постраничный обход. Теперь при известной оценке (одна страница) и без фильтров
   по времени — сразу «в архиве нет страниц» (Д-109).

## 5. Визуальные тесты окна

Окно проверялось вживую: снимки клиентской области при каждом изменении состояния (цикл снимков
каждые 200–1000 мс), плюс клики по кнопкам. Стадии: старт → инвентаризация → скачивание → сборка →
отчёт → «Готово»; отдельно «Пауза», «Остановить», ошибка инвентаризации.

| Кадр | Что видно | Вывод |
|---|---|---|
| старт | «Готов к запуску», 0 %, плитки пустые, журнал из одной строки | в порядке, кроме дефектов ниже |
| инвентаризация | «Инвентаризация архива 8 %», «Обработано 0/1844», журнал «адресов найдено: 1844» | процент и плитка расходятся — в 3.7.0 |
| скачивание | «Скачивание файлов 36 %, осталось 136 с», «635/1844», «18 КБ/с», «429: пауза 20 с» в журнале | читается, причины пауз видны |
| готово | «Готово 100 %», «1844/1844», «Битые / ошибки 4/104» красным | было «Готово» + зелёная точка — исправлено |
| остановлено | «Остановлено», кнопка «Начать» снова активна, прогресс 4 % | работает; остаточная полоса прогресса — в 3.7.0 |
| ошибка (нет сайта) | висело на 4 % около двух минут | исправлено (Д-109) |

Исправлено по итогам (Д-110…Д-112): журнал переносит длинные строки и сам прокручивается к
последней записи (путь к отчёту в строке итога раньше обрезался, а при 248 записях окно стояло на
первых); «Готово» при ненулевых ошибках стало «Готово, с замечаниями» с янтарной точкой; подсказка
под полем адреса больше не начинается символом «→» (его нет в шрифтах egui — рисовался пустой
квадрат), второстепенный серый стал темнее (замер по снимку: около 4,1:1 → норма).

Отдельный агент-дизайнер (после сбоя первого исполнителя — второй, с тремя снимками) дал восемь
замечаний; четыре вошли в релиз, остальные — в 3.7.0: расхождение процента и плитки, неактивные
кнопки, «Потоки» и «файлов/с» как «живые» метрики после завершения, подпись ошибок без пояснения
«из какого числа».

## 9. Чего этот документ не утверждает

- Linux-бинарники из релиза **не запускались** на этой машине: прогон в WSL не входил в задачу.
  Размеры и успешная сборка в конвейере — не то же самое, что работа под Linux.
- Проверка «путь длиннее 260 символов» сделана на Windows с включённой опцией длинных путей;
  поведение на системе с выключенной опцией подтверждается только тестами и кодом, не живым
  отказом (воспроизвести отказ на этой машине нельзя).
- Ответы агента-дизайнера и ревьюера — внешние мнения; в релиз вошло то, что подтверждено кодом,
  тестом или снимком экрана.
- Исчезновение ошибки «invalid gzip header» подтверждено косвенно: в журнале прогона после правки
  такой строки нет, но ресурс, который её вызывал, отдельно не воспроизводился — прямой проверки
  «тот же файл с неверным `Content-Encoding` теперь сохраняется» нет, есть только правка заголовка
  и её обоснование.
