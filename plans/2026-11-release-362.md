## 4. Проверки работой

### 4.1. След паники (Д-95)

Тест `crash::tests::panic_in_worker_is_recorded` паникует в потоке `engine-worker`; под `--nocapture` напечатал фактический файл:

```
2026-11-14 10:56:37Z thread=engine-worker at src\crash.rs:152:23
panic: намеренная паника для теста Д-95
--- backtrace ---
... (стек с кадрами std::panicking и thread::lifecycle) ...
--- end ---
```

Штатный вывод паники остался на месте: `thread 'engine-worker' (6348) panicked at src\crash.rs:152:23`. То есть хук пишет след и не подавляет сообщение.

### 4.3. Живой прогон (Д-97)

`site-restorer --cli --site example.com --out %TEMP%\sr-live-362 --limit 8 --workers 4`:

- код возврата 0; `ok` 1 из 1, файлов в копии 1, страниц 1, ссылок 0, битых 0;
- в итоге: `"archive":"http","archive_requests":9`;
- в отчёте: `<tr><td>Схема доступа к архиву</td><td class="n">http · 9 запросов</td></tr>`;
- в журнале одно сообщение: «архив: список недоступен, переключаюсь на http://web.archive.org»;
- `data/crash.log` не появился — без паники файл не создаётся.

Схема `http` в этом прогоне — не дефект: запрос списка по https не прошёл с этой машины (curl при этом отвечал 200), программа перешла на запасную схему и зафиксировала её до конца прогона, что и требовалось по ФТ-116.

## 8. Что не проверено (и почему)

1. **Окно GUI руками** — не открывалось: проверялись сборка, `--version` оконной сборки (3.6.2) и тесты, но не внешний вид и не показ сообщения о панике в окне (сообщение вызывается только при панике; в тестах окно отключено флагом `install_with(..., false)`).
2. **Linux-бинарники не запускались** — собраны конвейером, размеры и glibc-пол проверены в CI, но на этой машине не исполнялись (кросс-запуск Linux на Windows невозможен).
3. **Чистая Windows без Visual C++ Redistributable** — статический CRT проверяется в CI (`dumpbin /dependents`), вручную на чистой системе не запускалось.
4. **`Retry-After` датой на живом сервере** — проверено тестом и разбором кода; сервер архива за прогон дату не присылал.
5. **Документы вне `plans/`, `docs/`, корня** — гейт `tools/audit-docs.py` по всему репозиторию (42 файла `.md`) нашёл 2 дефекта только в `scratch/impl/*.md` (рабочие заметки, в git не входят, в поставку и документацию не попадают).
