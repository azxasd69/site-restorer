# Архитектура Site Restorer 2.0

Документ описывает алгоритмы восстановления сайта из веб-архива, решения по
многопоточности и устойчивости к ограничениям, проверку на разных CMS и упаковку.

---

## 1. Конвейер

```
[1] Инвентаризация CDX → [2] Параллельная загрузка → [3] Сборка → [4] Проверка → [5] Отчёт
```

### 1.1 Инвентаризация

1. Пробный запрос `showNumPages=true&output=json` — узнаём число страниц CDX.
   Формат ответа бывает трёх видов (`{"pages":N}`, `[["numpages"],["N"]]`, `N`),
   парсер поддерживает все.
2. Если страница одна — один запрос с `collapse=urlkey&limit=50000`.
3. Если страниц много — постраничный обход `&page=i` (до 200 страниц),
   с прогрессом в интерфейсе. Так большие сайты не «висят» на одном запросе.
4. URL нормализуются: `http→https`, `www.` вон, порт 80/443 вон, `#` отрезается.
   Один адрес = одна запись; из нескольких снимков берётся самый свежий.

### 1.2 Загрузка

**Параллельность по типам.** Задачи не сортируются «сначала все HTML», а
перемешиваются по кругу: html, code, img, other, html, code… Поэтому все четыре
полосы прогресса двигаются одновременно — это и просил пользователь.

**Возобновляемость.** Перед стартом сканируется `mirror/`; файл считается
готовым, если существует и его размер > 0. Повторный запуск не качает заново.

**Режим `id_`.** `http://web.archive.org/web/<ts>id_/<url>` отдаёт исходные байты
без панели Wayback и без переписанных ссылок.

**Fallback.** Если последний снимок отдаёт 404 — перебор ближайших годов
(текущий, −1, −2).

### 1.3 Адаптивная конкурентность (AIMD)

```
каждые 3 секунды:
  bps = байты за окно / время окна
  если были 429:            limit = max(2, limit/2)
       серия из 3 окон:     пауза 120 с, limit = 2
  иначе если bps >= 0.95*prev и файлы > 0:  limit = min(24, limit+1)
  иначе если bps <  0.60*prev:              limit = max(2, limit-1)
```

Реализация — `Gate` на `threading.Condition`: поток ждёт, пока `inflight < limit`;
изменение лимита мгновенно влияет на всех. Это «additive increase, multiplicative
decrease» — классический алгоритм для неизвестной пропускной способности.

**Почему 2..24.** При 10 Мбит/с и странице ~150 КБ предел канала ≈ 8 файлов/с;
по закону Литтла при задержке 1,5–3 с нужно 12–24 запроса в полёте. Но реальный
потолок задаёт архив, а не канал: на практике устойчиво работают 3–6 потоков.
Старт с 2 — чтобы не получить блокировку на первом же burst.

### 1.4 Работа с ограничениями архива

Официально (blog.archive.org, 15.09.2026) Internet Archive включил защиты от
высоконагруженного автоматического трафика и отдаёт 429 при превышении.
Численных квот не публикует. Поэтому:

| Механизм | Назначение |
|---|---|
| `Retry-After` | точная пауза, если сервер её сообщил |
| экспоненциальная пауза + джиттер | 20→40→80 с, чтобы не бить в стену синхронно |
| «предохранитель» | серия 429 → 120 с тишины и сброс потоков к 2 |
| плавный разгон | старт с 2 потоков, +1 каждые 3 с |
| keep-alive | одно TCP-соединение на поток, меньше мусора в сети |
| http-fallback | при обрывах TLS переключение на http |
| честный User-Agent | `SiteRestorer/2.0 (…respectful crawler…)` |

Чего нет намеренно: подмены UA под браузер, ротации IP, обхода капчи.
Практика показала: именно маскировка под браузер вызывает блокировку
«suspected abusive bot traffic», а честный UA + 3–4 запроса/с работают стабильно.

### 1.5 Сборка

Копия `mirror → site` с переписыванием ссылок в относительные:
`href/src/srcset/action/poster/data-src/data-bg`, `url()` в CSS и inline-стилях,
удаление `<base href>` на исходный домен, `https://host/ → /` в JS.

Универсальные эвристики (работают для любой CMS):
- **кэш с хэшем в имени** (Bitrix `bitrix/cache/.../template_<hash>_v1.css`,
  WordPress `?ver=`, MODX `assets/.../style.min.css?v=`): если точного файла нет,
  подставляется файл того же типа/каталога;
- **миниатюры** `upload/resize_cache/iblock/<aa>/<size>/<name>` → оригинал
  `upload/iblock/<aa>/<name>`;
- **поиск по имени файла** в пределах той же глубины пути — спасает при смене
  хэша каталога.

### 1.6 Проверка и отчёт

Обход всех HTML, подсчёт внутренних и битых ссылок; `report.html` с покрытием,
разбивкой по типам и списком ошибок.

## 2. Разбор пользовательского ввода

`sanitize.py` приводит к домену всё, что можно вставить в поле:

| Шаг | Что делает |
|---|---|
| NFKC + удаление zero-width/BOM/NBSP | невидимый мусор от копипаста |
| замена типографских кавычек/тире | «…», “…” |
| распознавание ссылок архива | `web.archive.org/web/<ts>/https://site/` → исходный URL |
| распознавание редиректов поиска | `google.com/url?q=`, `yandex…?url=`, `bing…` |
| выбор токена | первый фрагмент, похожий на хост |
| отбрасывание пути/порта/точки | `site.ru:8080/x` → `site.ru` |
| нижний регистр, снятие `www.` | `WWW.SITE.RU` → `site.ru` |
| кириллица: 2 гипотезы | (а) набрано в русской раскладке → обратное отображение ЙЦУКЕН→QWERTY; (б) настоящий IDN-домен → punycode |
| валидация | метки `[a-z0-9-]`, TLD ≥ 2 букв |

Покрыто 14 тестов, включая `зкщлгзщдюкг → prokupol.ru`, `прокупол.рф → xn--…`,
ссылку из архива и ссылку из Google. Все проходят.

## 3. Интерфейс

- Одно окно, `ttk`, тёмный журнал, крупная полоса общего прогресса.
- Четыре полосы по типам + строка состояния со скоростью, потоками и ETA.
- Переключатель языка RU/EN — тексты собраны в словаре `STR`, переключение
  применяется на лету и сохраняется в `%APPDATA%\SiteRestorer\config.json`.
- Кнопка «Справка» — окно с описанием работы, форматов адреса и ограничений.
- Поток загрузки общается с UI через `queue.Queue`, UI опрашивает очередь
  каждые 120 мс (tkinter не потокобезопасен).

## 4. Проверка на разных CMS

| Сайт | CMS | Инвентарь | Скачано | Сборка |
|---|---|---|---|---|
| prokupol.ru | Bitrix + Aspro Max | 1638 URL | 20/20 (тест) | OK |
| craftcms.com | Craft CMS | 3000+ | 15/15 | OK |
| laravel.com | Laravel | 3000+ | 12/12 | OK |
| wpmayor.com | WordPress | ~10 тыс. | 10/12 | OK |
| modx.com | MODX | 113 страниц CDX | 10/10 | OK |

Во всех случаях: старт → инвентаризация → запись файлов в `mirror/` → сборка
`site/` → отчёт. Различия CMS на алгоритм не влияют: инструмент работает с
архивными URL, а не с движком.

## 5. Упаковка

- Python 3.14 + tkinter, **только stdlib** — ноль внешних зависимостей.
- PyInstaller 6.22.3: `--onefile --windowed --icon app.ico`.
- Итог: один файл ~13 МБ, не требует установки и Python.
- Альтернативы на машине: .NET (только runtime, без SDK), Go, Rust (нет MSVC
  линкера) — отвергнуты как более трудоёмкие при том же результате.

---

## 6. Известные ограничения

- Нет докачки больших файлов по HTTP Range (файл берётся целиком).
- Нет встроенного локального сервера — копию открывают отдельным сервером.
- При громадных архивах (>200 страниц CDX) инвентарь усекается с предупреждением.
- Кэш CMS с другим хэшем подставляется эвристически: стили могут отличаться
  версией, но не пропадают.
