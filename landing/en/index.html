Advantages

Six things that decide whether a copy works out

Not a feature list, but what you notice in the first half hour: speed, intact markup, honest numbers, archive completeness, the ability to continue later, and readable text in the files.

01 · SPEED

Multithreaded download

Pages, styles, scripts and images are fetched at the same time, and the thread count adapts to the archive's response: it grows while speed holds and drops when the server starts to slow down.

  • starts with two threads, working ceiling is 24
  • HTTP 429 means a pause as the server asks, not a failed file
  • optional rate limit when the link is shared
1,200 files ≈ 4 minutes
02 · RESULT

Automatic local assembly

What you get is not a folder of downloaded files but a working site: links are rewritten to relative paths, so the copy opens without the original domain and without the internet.

  • attributes, image source sets, URLs inside styles and scripts
  • CMS cache files with a hash in the name, thumbnails instead of originals
  • the base tag is removed so paths resolve from the file
75,387 links rewritten
03 · TRUST

Honest completeness report

The report counts separately what came back, what the archive never stored, and what failed to download. Those are three different numbers and must not be mixed.

  • coverage by file type and size from the actual files
  • broken links found by walking the finished pages
  • an explicit warning that the copy is static
report.html works offline
04 · COMPLETENESS

Addresses from every archived year

The index returns everything the crawler stored over ten years, not just the latest snapshot. When there is no snapshot for the chosen date, neighbouring years are tried.

  • up to 50,000 addresses and 200 index pages per run
  • the index response is streamed: size and record count are visible
  • truncation is not hidden — the log says so
9,476 snapshots in one run
05 · CONTINUATION

Resume and re-run

A large site takes hours. You can stop the run, close the program and come back later: finished files are not requested again and work continues from where it stopped.

  • a file counts as done only if it exists and is not empty
  • an unfinished file stays under a temporary name
  • folder structure and inventory are read by newer versions
re-run without re-downloading
06 · READABILITY

Encodings and file integrity

Older sites were written in windows-1251 and KOI8-R. The program converts text to UTF-8 based on the content rather than the declaration, so Cyrillic does not turn into garbage.

  • byte order mark, declared charset, statistical assessment
  • double-encoded text is repaired
  • binary files behind a page address are copied as-is
7 encodings → UTF-8

How it works

Four steps and the copy is on disk

Five stages inside: inventory, download, assembly, verification, report. The window shows the step, the stage and a log line with a timestamp for every request.

  1. Paste the address

    A domain, a link with tracking parameters or an archive URL. The input is cleaned automatically, including a wrong keyboard layout and IDN domains.

  2. Choose a folder

    Documents\SiteRestore\site by default. Any drive and directory will do.

  3. Press “Start”

    The run continues in the background: progress by file type, request log, a stop button at any moment.

  4. Open the report

    report.html shows coverage, size and broken links. The copy is opened through a local server.

PowerShell · command line 
SiteRestorer-windows-x64-cli.exe --site yoursite.ru --out D:\mirror --lang en
site\the finished copy, open it with a local server
mirror\raw files from the archive
data\inventory.jsonl — what was fetched and when
report.htmlcoverage and losses
PowerShell · local server 
cd Documents\SiteRestore\site
python -m http.server 8080

Why a server is needed. The copy is plain HTML files, but links like /catalog/ will not open by double-click. Any local static server works; if Python is installed, the two lines on the left are enough.

For scripts and schedulers there is a command line mode: --site, --out, --workers, --rate, --limit, --lang, and at the end a RESULT {…} line with a JSON summary.

The detailed breakdown is in the project documentation. Running the same job on your own domain takes a couple of minutes.

What did not come back, and why

  • Product images. 2,510 images were never stored by the archive: no index record, a 404 for any year. That is an archive loss, not a program failure.
  • CMS dynamics. Cart, login, search and AJAX catalogue filters do not work in a static copy — they need a backend and a database.
  • Template cache. File names carry a build hash. A file of the same type is substituted — styles survive, the version may differ.

When this helps

The host lost the data

The domain resolves, the server is silent, there are no backups. The archive is the only source of content: pages, articles, catalogue.

The site was closed or abandoned

You need a copy for the record, for a migration or to hand over to a client — without admin access and without the old CMS.

You need an older version

Compare what the site looked like a year ago, restore a removed section or a lost page.

Limits

What to understand before the first run

The tool promises no miracles: it carefully extracts what the archive actually kept and states what will not be there.

comes back

  • pages and the section structure
  • styles, fonts and page scripts
  • images the crawler stored
  • documents and PDF files
  • addresses from every snapshot

does not come back

  • the database: products, orders, CMS articles
  • cart, account login, search, AJAX filters
  • images the archive never kept
  • dynamic requests and APIs
  • wishes instead of evidence: no placeholders
Ethics and law. The tool is meant for personal archiving and recovery of your own sites. It does not bypass protection, does not spoof a browser, only reads the archive and never sends your data anywhere. A copy of someone else's site is not a licence to publish it.

The archive sets the pace: the Internet Archive limits request rates per IP, so large sites take hours. A run can be stopped and resumed, and instead of filling gaps the program will show them — no placeholders.

FAQ

Short answers to the usual questions

Do I need Python or other software?
No. The main build is a Rust binary with no interpreter: the application starts on a clean Windows install. Python is only needed if you choose python -m http.server as your local server — any other static server works too.
What if the archive kept nothing?
The report will say so and nothing will be invented. Try the domain with and without www, and neighbouring years: the closest snapshots are tried for every address.
How long does a recovery take?
It depends on the site size and the archive limits. A small site takes minutes, thousands of addresses take hours: the Internet Archive limits request rates per IP. Progress, size and remaining time are visible in the window, and resuming lets you stop and continue later.
Will product images and photos come back?
Only if the archive stored them. Internet Archive crawlers often capture pages but not every image: in one case 2,510 product images were absent from the archive entirely while the text part survived.
Will the cart, login and search work?
No. The copy is static: pages, styles, scripts and files are restored. Anything that needs server logic and a database (cart, login, AJAX filters) will not work.
Is this legal?
The tool is meant for recovering your own sites. It does not bypass protection, does not spoof a browser and does not hide. Publishing a copy of someone else's site is not allowed; respect the Internet Archive terms and the copyright of content owners. The application itself is MIT licensed.
