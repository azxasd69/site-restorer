Hosting lost your data: what to do in the first hours

Updated 10 November 2026 Read: 8 minutes Practice: hosting, domain, archive

In short

  1. Freeze first, fix later. Every change you make now can destroy evidence or backups you have not seen yet.
  2. Write to the host in writing and ask for the account archive with the deletion date. That answer is your deadline.
  3. The domain is the only thing you cannot rebuild from an archive: renew it before anything else.
  4. Do not change DNS until you have pulled the files, database and mail that may still be there.
  5. The web archive is a fallback, not a restore: pages come back, the database does not.

A hosting failure is not one event but several with different odds. Until you know which one you are in, most actions make things worse: pointing the domain elsewhere wipes the records you still need, and installing a fresh CMS on the same address finishes off whatever was left of the search index.

1. Which of the five failures is this

ScenarioHow it looksChance of recovery
Host closed the accountsite down, panel inaccessible, notice by emailhigh while provider backups exist
Domain expiredparking page, placeholder or someone else's sitedepends on the grace period; near zero afterwards
Site deleted from the panelaccount alive, files and database gonemedium: backups may exist
Compromisesite loads, but with redirects or foreign contenthigh: the data is still there
Suspended after a complaintsuspension notice from host or registrarmedium: needs the reason resolved

The difference matters: in the first and third cases the data usually still exists physically and everything comes down to how fast you ask. In the second, the question is no longer about content but about who owns the address.

2. The first thirty minutes

  • Do not touch DNS. While the domain still points at the old host, you can pull files, database and mail if access is restored.
  • Do not install a new CMS on the same domain: it overwrites leftovers and breaks link recovery.
  • Do not delete old emails. They hold the contract, logins and ticket numbers the support team will ask for.
  • Do not pay the first "we restore sites in 24 hours" offer before you know what is available for free.

One action belongs in the first thirty minutes: a written request to the hosting support. Ask specifically whether files and database still exist, until when, and whether you can receive the account archive. A written answer timestamps the fact that the data existed — useful if it later "disappears".

3. The domain comes first

Content can be rebuilt from archives and copies. A domain cannot: once it is released, anyone can register it, and getting the address back means buying it from the new owner.

  1. Check the expiry date and status in WHOIS. Statuses such as redemptionPeriod, pendingDelete or clientHold tell you how far along the process is.
  2. Renew immediately if the domain is still yours. Do not wait for "later".
  3. Restore access to the registrar and the admin mailbox. If that mailbox is lost, it is the first task — more urgent than the site.
  4. Do not transfer the domain to another registrar while the situation is unclear: transfers complicate disputes.

If the domain is already gone, the only lawful routes are buying it back or moving to another address. The second is cheaper but requires redirects and a fresh index.

5. When the archive is all that is left

Then the goal changes. You are not restoring an application, you are rebuilding a readable copy at the same addresses:

  1. Check that the site was captured at all — the snapshot calendar answers that.
  2. Export the address list from the CDX index: it shows the real scope.
  3. Download each address in id_ mode, so links point at the original domain.
  4. Assemble the copy locally and open it with the network off.
  5. Publish at the same URLs and ask search engines to re-crawl.

Be explicit with yourself and with clients about limits: the archive holds what a crawler saw. Product images, downloads, pages behind a login and anything a database generated are usually missing, and forms will not work in a static copy.

6. Keeping the search traffic

  • Keep the same URLs. If the structure survives, pages return to the index quickly.
  • Add 301 redirects from old paths if the structure must change.
  • Tell search engines: sitemap, IndexNow, and the re-crawl tools in the webmaster console.
  • Do not block indexing during the work; serve a temporary 503 with Retry-After instead.
  • Keep the analytics properties alive. Historical data is the only way to compare before and after.

7. Checklist

  • ☐ Written request to hosting: do files and database exist, until when
  • ☐ WHOIS checked: expiry date, statuses, renewal done
  • ☐ Admin mailbox access restored
  • ☐ Own backups, repository and developer copy checked
  • ☐ Web archive checked: snapshots and their dates
  • ☐ DNS left untouched until data is pulled
  • ☐ Local copy assembled and opened offline
  • ☐ Decision made where the rebuilt site will live
  • ☐ Redirects and re-crawl arranged

FAQ

Can a site be recovered if the host deleted the account?

Ask support first: most providers keep account backups for a limited period after deletion. If they refuse, the remaining sources are the web archive, search caches, developer copies and your own exports.

What should I do first?

Renew the domain if it is still yours, and do not change DNS until you have pulled whatever data is left. The domain is the only piece an archive cannot rebuild.

The site was deleted long ago and the archive is empty. Now what?

Check search caches, saved pages in browsers, backup exports, newsletters, contractor copies and repositories. With no source at all, the content cannot be recovered — the site has to be built again.

Will I lose search traffic?

Some traffic is lost unavoidably. Keeping URLs, adding 301 redirects, submitting a sitemap and using IndexNow and re-crawl tools limits the damage.

Should I pay a service that promises recovery in a day?

Find out first whether the host and the archive have anything: that is free and takes an hour. Paid services usually deliver the same static copy you can assemble yourself.
